# 同类产品调研：T3 Code 与 Clowder AI（2026-11-11）

目的：回答“我们的接力是不是做复杂了”。两份完整报告：[T3 Code](t3code-2026-11-11.md)（`pingdotgg/t3code`，commit `b883156`）、[Clowder AI](clowder-ai-2026-11-11.md)（`zts212653/clowder-ai`，commit `42017e0`）。

局限：只读源码、文档与 issue，没有运行它们的产品；调研者没有审读我们的实现，对我们的建议是按描述推的；“没人抱怨”来自标题级的 issue 检索，隐私类问题通常也不会有人报。

## 结论

两家都在解决同一个问题，骨架和我们一样：自己存规范对话，每家 Harness 一个原生会话，记住每家看到哪里，只补增量，回原来那家续原会话。它们省掉的是“证明送到了”和“防御”两层；它们用户受伤的地方，是我们认真做了的另外几处。所以该做有选择的减法。

## 按功能点

| 功能点 | 我们（2026-11-11） | T3 Code | Clowder AI | 我们的方向 |
|---|---|---|---|---|
| 交接内容 | 叙述化，5 档，带“状态与风险”等节 | 预算内挑原文，放不下的整条省略 | 没看过的逐字消息加一行概括 | 2 档，只放事实 |
| 被省略的部分 | 只记账 | 记账并给读回指针 | 给读回指针 | 加读回指针 |
| 记住看到哪里 | 状态机（4 状态 × 14 事件）、纪元、清空下限 | 每次现算，三值标记 | 游标加冷热状态 | 游标加一个边界 |
| 送达确认 | 三种证据，事后读对方历史核对 | 只记发出与被接受 | 一律“不知道” | 事后核对退出主路径 |
| 送达不明时 | 补发一次，之后只发原话 | 丢原生会话开新的（出过事） | 多给，并告诉模型 | 保留补发一次，加提示头自述 |
| 原生清空 | 探测并确认 | 自己接管 | 不处理 | Hub 接管 |
| 交接超窗口 | 压缩，放不下只发原话 | 报错卡死（27 个 issue） | 丢最旧的，出过超窗 | 不变 |
| 取消与失败的回合 | 逐格定义 | 漏过一类 | 只记终态 | 不变 |
| 命令回合不带交接单 | 按各家原生解析 | 只认两个命令 | 不适用 | 不变 |
| 跨厂商同意 | 3 档，按端点识别厂商 | 没有 | 没有 | 首次一行提示加日志 |
| 脱敏 | 三层含熵规则 | 没有 | 没有 | 精确替换加常见形状 |
| 探针门控 | 有（已降为标注） | 静态声明 | 静态声明 | 静态声明加升级时的契约检查 |
| 设置项 | 6 个 | 1 个环境变量 | 很多，吃过亏 | 2 个以内 |
| 界面可见 | 分隔线、原文、提示条 | 一条分隔线，看不到内容 | 有“实际输入”面板 | 不变 |
| Harness 之间委派 | 没有 | 有，官方主推 | @提及，有深度与空转上限 | 值得做 |
| 跨模型评审 | 没有 | 没有 | 有 | 值得做 |

## 它们吃过的亏（留着我们对应的做法）

- T3：预算依赖对方原生用量，算错后线程卡死；送达标记误判丢掉一个 55 万 token 的原生会话；取消的回合没交过去却报告省略 0 条；悄悄开新原生会话界面无痕；清空后重启旧会话复活。
- Clowder：把“没记录”当成“变了”，升级后 3 小时自动封存 55 个会话；靠匹配错误文案判断续接失败，某个 CLI 升级后线上停摆 9 天而模拟测试全绿；按时间戳排序导致历史因果倒置。

## 值得借的

提示头里告诉模型“这是冷启动还是热续接、这部分可能重复”；交接单里给读回指针；Codex 的 `thread/inject_items`（把交接内容直接追加进原生历史，用户消息保持原样）；委派子任务（只给任务、不复制历史）；录制真实 Harness 转录做回放测试。
