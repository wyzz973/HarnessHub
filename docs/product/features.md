# 功能清单

2026-11-14，对应 main `916d17a`。只支持 macOS，从源码运行，界面只有中文。

证据分两级标在条目后面：**真机**是在本机真实安装的 Harness 和真实模型上跑过；**合成**是只有合成测试（假 Harness 或本地确定性服务）。没标的，代码在 main 上，没有单独的验证记录。每次真机跑了什么、没验什么，见[决定记录](../decisions/LOG.md)；每家每项怎么适配、真机核对到哪，见[适配矩阵](../contracts/harness-adapters.md)。2026-11-09 的清单留作快照：[mvp-2026-11-09.md](mvp-2026-11-09.md)。

## 一句话

在你的 Mac 上，用一个对话驱动你已经装好、登录好的六家 Harness。一件任务的全部上下文由 Hub 管，各家只管干活：可以换一家接着做，也可以把一段活交给另一家。

## 六家 Harness

| Harness | 接入 | Hub 的工具与说明怎么到它那里 | 一轮进行中插话 |
|---|---|---|---|
| Claude Code | ACP，经 `claude-agent-acp` 绑定你自己的 `claude` | 会话级 MCP，系统提示追加 | 能（`_session/steering`） |
| Codex | app-server | 线程级 MCP，developer instructions | 能（`turn/steer`） |
| OpenCode | ACP（`opencode acp`） | 会话级 MCP，说明随 MCP 服务器给 | 原生没有 |
| DeepSeek Harness | ACP，经 `dsh` 自己的 profile | 会话级 MCP，说明随 MCP 服务器给 | 原生没有 |
| Hermes Agent | ACP，附着到你在跑的网关 | 会话级 MCP，说明附在第一条消息后面 | 原生没有 |
| OpenClaw | ACP，加上你自己的 OpenClaw 网关 | 每段对话一条 Hub 命令，它用自己的 exec 工具调；说明附在第一条消息后面 | 原生没有 |

- 每家一份适配声明（`src/adapters/flavors/`）。只用按会话、按进程能设的入口，不改你的 Harness 配置。
- 按各家最新的正式版适配（[ADR-053](../decisions/0053-latest-version-baseline.md)）。
- Cursor、Gemini CLI、Pi 也有驱动，已冻结、默认隐藏。WorkBuddy 还没接。

## 1. 一个对话，用任何一家

- 对话属于 Hub，不属于哪一家。两条消息之间就能换 Harness、模型、思考强度，不用点“应用”。
- 权限五档（只规划、每步询问、自动改文件、自动执行、完全放行）和思考五档（关、低、中、高、最高），六家都有。原生有的用原生设置；原生没有的，由 Hub 按档位答复它的权限请求，替你做的决定都留成审批条目。真机：六家的五档和中途改档逐格跑过（2026-11-13），个别格子的例外写在矩阵里。
- 原生能力接出来：审批（⏎ 允许、esc 拒绝）与提问、计划模式、`/` 命令、子 Agent、用量；附件（文件、图片、音频）按各家自己的输入方式发，模型收不了的在发出前拒绝。DeepSeek Harness、Hermes 不报回合用量，Hub 读它们自己的记录来算。真机。
- 恢复、分叉、编辑并重发、重试。能原生分叉的四家走原生；DeepSeek Harness、OpenClaw 由 Hub 带上历史。真机（2026-11-13，六家）。
- 清空（单独输入 `/clear`、`/new`、`/reset`）由 Hub 接管：开一个新的原生会话。
- 速度档：Codex 用 `serviceTier`，Claude Code 用 `fast`（只有 Opus 一类模型有）。Codex 真机，Claude Code 的快档没真跑过。
- 回复流式显示，刷新不丢、不重发；关掉页面不取消回复；结果未知的执行不会被自动重跑。
- 不设总量上限：回合没有时间墙（跑得久只提示），并行的对话不设固定个数，同一个目录里的几段对话可以同时干活（会提示）。

## 2. 多家协作

- **换一家接着做。** 新接手的一家拿到一份交接单：用户原话、每一家做了什么、改了哪些文件。预算是它窗口的一半，放得下就整段带；回到原来那家时只补它没看到的。真机。
- **委派。** 你从菜单发起，或者 Harness 自己调 `hub_delegate`，把一段活交给另一家。它在自己的子对话里做，用同一个工作区；结果自动告诉原对话；最多三层。读得了记录的一家，被委派时先拿到用户的原话和任务状态，做过的事要用再去读。真机：六家都当过发起方（2026-11-13）。
- **任务上下文。** 一件任务是起头的对话，加上它委派出去的所有对话。
  - 任务板：目标、约束、决定。用 `hub_remember` 记，每条带编号、可以撤；变了以后，任务里每一家下一轮都会带上。
  - 记录目录 `<数据目录>/context/<任务>/`：每段对话每一轮的全文（原话、回复、每次工具调用的输入和输出、改动），只读，各家用自己的读文件工具读。OpenClaw 读不到它自己工作区以外的文件，改用 Hub 命令。
  - 状态块 `STATE.md`：目标、约束、做到哪、改过的文件、用户最近说的话，由 Hub 从记录里拼出来。在它接手或者压缩过之后，整块给它一遍。
  - 一轮进行中有了变化（任务板变了、原对话里用户又说了话、别的对话改了它碰过的文件），随它下一次调 Hub 工具的答复送到。
  - 别的对话改了文件会告诉它；委派的结果连同改动的文件和最后运行的命令，一起回到原对话。
- **压缩。** 由各家自己做。它一压缩，Hub 就把任务状态随下一次工具答复送回去。只有上一轮超出了窗口，或者原生会话找不回来了，Hub 才换一个新的原生会话接着做。按用量换会话默认关（`HARNESSHUB_RESEAT_AT`）。
- **进度。** 各家用 `hub_update_plan` 列清单、用 `hub_wrap_up` 写小结，显示在输入框上面和右侧栏。第一轮的小结可以顺带给对话起名。
- 真机：[委派上下文尺子](../verification/delegation-ruler.md) 2026-11-14 按默认设置跑了一次（Claude Code + Haiku、DeepSeek Harness、Codex）。S1–S13 过；S14 带上 Claude Code 的提早压缩开关单独跑了一次，过；S15 里 Codex 过，Claude Code 撤掉了条目，但列了数据目录的上一层，按“越出工作区”判了不过。

## 3. 编码工作台

- 结束的一轮收成一行，下面一张改动卡（文件树、增减行数）。失败或被停下的一轮不收。
- 改动页：范围可以是本轮、这段对话、其他对话，或者 Git 范围（未提交的、相对默认分支或任一分支、某个提交）。能按文件夹看、并排看差异，点行号写评语，评语连同那几行放进输入框。
- 每段对话可以开自己的 Git 工作树（默认在 `~/HarnessHub/worktrees`，分支按标题起名）。每轮前后拍快照（`refs/harnesshub/checkpoints/…`，不动你的暂存区、HEAD 和分支）；“编辑并重发”时可以把文件还原到那一轮之前，只限对话自己的工作树。
- 提交、推送、建 PR（用你本机登录的 `gh`），都只在你点了才做。
- 终端：在对话的工作区里开你自己的登录 shell。收起或换对话不会断，回来先重放之前的输出；能分屏、分标签、跑 package.json 的脚本，选中的内容能放进输入框。
- 插话：一轮进行中再发的话插进这一轮（Claude Code、Codex）；另外四家只能等这一轮结束后发。真机。
- 在编辑器里打开、在访达里显示、按标签读文件。
- 侧栏：按项目或按状态分组；置顶（可拖动排序）、稍后提醒、归档、最近删除（可恢复、可彻底删除）、多选批量操作、⌘Z 撤回、标为未读。别的对话等你处理时，标签页图标上带数字。
- ⌘K 搜所有对话的消息，⌘F 在对话里查找；命令面板；快捷键可以改；临时对话（不选文件夹，默认放在 `~/HarnessHub/chats`）；选文件夹用 macOS 自己的选择框。
- 真机：以上在试用服务上逐项点过，主要用 Claude Code + Haiku（2026-11-14）。建 PR 和推到真实的远端只有合成测试。

## 4. 管理本机的 Harness

- 只认官网方式的安装（npm、Homebrew、厂商脚本、uv），有几份就列几份。
- 安装、升级、卸载：先把命令列出来给你看；升级后按它自己的方式重启后台服务并核对；卸载只删程序，保留数据。真机（2026-10）。
- 能力页：跨 Harness 统一管理技能、MCP、说明文件、子 Agent 和插件开关。只改用户级配置，写之前给出差异并留备份，可以撤回。真机（2026-10）。
- 能导入某一家自己在这个工作区里的原生会话。

## 数据和登录

- 都在 `--data-dir` 里：每个对话一个只追加的 JSONL 文件（`sessions/`），列表和翻页用可重建的索引；任务记录目录在 `context/`；工具详情与附件、管理、能力各一个 SQLite。
- 2026-11-12 起对话换了存法，旧格式的对话库 `gateway.sqlite` 不再读取，留在原处不动。
- 服务只监听 `127.0.0.1`，用启动时打印的一次性链接登录；有活动就续期，8 小时没有活动才失效。

## 没做

- WorkBuddy 接入。
- Provider 统一管理：页面里是关着的，各家用自己配好的模型。
- 原生宿主池（[ADR-056](../decisions/0056-native-hosts-and-sessions.md)，一个进程服务多段对话）：现在是每段对话保留自己的原生进程。
- 上下文“按工作集少装”：量过，整段带过去只多等三四秒，先放着。
- 两轮之间由 Hub 请它先压缩一次。
- 委派还差三样：在父对话里停掉子对话、子对话做完时发系统通知、委派时选模型和档位。
- 打包分发：还没有发布版。终端用的 `node-pty` 要签名公证，`spawn-helper` 要保留执行权限；终端只在 Chromium 里试过。

## 原生做不到

- 插话：OpenCode、DeepSeek Harness 进行中再发会被拒；Hermes、OpenClaw 会把它当成新的一轮，或者先取消正在跑的那一轮。
- OpenClaw：它的压缩 Hub 看不到，状态要等下一轮开头才说；它的工具改的是它自己代理工作区里的文件，Hub 记不到这些改动；只规划档下它拒绝一切命令，Hub 的工具用不了。
- DeepSeek Harness 的沙箱在会话建立时就定了，中途改档只改得了 Hub 的答复。
- OpenCode、Hermes 没有沙箱，“自动执行”管不住越出工作区的操作。

## 只有合成测试，或没核对

- 建 PR、推到真实的远端；Claude Code 的快档。
- 超出窗口、原生会话找不回来之后换会话。
- 状态块不截断、`STATE.md` 在一轮中途刷新、经记录文件送达变化。
- DeepSeek Harness、Hermes、OpenClaw 的压缩场景；Hermes、OpenClaw 的原生提问。
- 插话被拒、页面拿不准它收到没有；在归档的对话里发消息时自动取消归档。
- 消息搜索翻到第二页、⌘F 跳到还没读进来的早期轮次、相对默认分支的范围。
