# 功能清单

2026-11-15，对应 main `6329e6b`。只支持 macOS，从源码运行，界面只有中文。

证据分两级标在条目后面：**真机**是在本机真实安装的 Harness 和真实模型上跑过；**合成**是只有合成测试（假 Harness 或本地确定性服务）。没标的，代码在 main 上，没有单独的验证记录。每次真机跑了什么、没验什么，见[决定记录](../decisions/LOG.md)；每家每项怎么适配、在现在的驱动上核对到哪，见[适配矩阵](../contracts/harness-adapters.md)。2026-11-09 的清单留作快照：[mvp-2026-11-09.md](mvp-2026-11-09.md)。

## 一句话

在你的 Mac 上，用一个对话驱动你已经装好、登录好的七家 Harness。一件任务的全部上下文由 Hub 管，各家只管干活：可以换一家接着做，也可以把一段活交给另一家。

## 七家 Harness

每家走它自己最完整的官方接口（2026-11-14 起照 T3 Code 的做法逐家重接）。

| Harness | 接入 | Hub 的工具与说明怎么到它那里 | 原生回退 | 原生分叉 |
|---|---|---|---|---|
| Claude Code | Claude Agent SDK，驱动你自己的 `claude` 和登录 | SDK 会话的 MCP 服务器，系统提示追加 | 有 | 有 |
| Codex | app-server | 线程级 MCP 配置，developer instructions | 有 | 有 |
| OpenCode | Hub 自己起的 `opencode serve --stdio` | 运行时加进会话的 MCP 服务器，会话自己的说明条目 | 有 | 有 |
| DeepSeek Harness | 它的 Web 宿主，用不了就退回 ACP | 只给 Hub 起的进程用的覆盖配置挂上 MCP 服务器，说明随 MCP 服务器给 | 没有 | 有 |
| Hermes Agent | 它自己的网关协议，附着到你在跑的网关 | 会话的 MCP 服务器，说明附在第一条消息后面 | 有 | 有 |
| OpenClaw | Gateway WebSocket，用 Hub 自己配对的设备 | 每段对话一条 Hub 命令，它用自己的 exec 工具调；说明附在第一条消息后面 | 有 | 有 |
| CodeBuddy Code | ACP（npm 版 `codebuddy --acp`） | 会话级 MCP，说明附在第一条消息后面 | 有 | 没有 |

- 每家一份适配声明（`src/adapters/flavors/`）。只用按会话、按进程能设的入口，不改你的 Harness 配置。
- 按各家最新的正式版适配（[ADR-053](../decisions/0053-latest-version-baseline.md)）。真机核对用的版本：Claude Code 2.1.325、Codex 0.169.0、OpenCode 2.3.0、DeepSeek Harness 0.2.2-rc.1、Hermes v0.23.1、OpenClaw 2026.11.3、CodeBuddy Code 2.184.0。
- 一轮进行中插话，七家都是原生的，插进这一轮的下一步。
- 没有原生回退或分叉的，由 Hub 带上历史开一个新的原生会话。
- CodeBuddy Code 顶替了 WorkBuddy：WorkBuddy 应用的登录只交给它自己的侧车，Hub 起的进程用不了，所以改接 npm 版，由你在它的命令行里登录一次。
- Cursor、Gemini CLI、Pi 也有驱动，已冻结、默认隐藏。

## 1. 一个对话，用任何一家

- 对话属于 Hub，不属于哪一家。两条消息之间就能换 Harness、模型、思考强度，不用点“应用”。
- 权限五档（只规划、每步询问、自动改文件、自动执行、完全放行）和思考五档（关、低、中、高、最高），七家都有。原生有的用原生设置；原生没有的，由 Hub 按档位答复它的权限请求，替你做的决定都留成审批条目。真机：2026-11-13 六家的五档和中途改档逐格跑过，那是换驱动之前；换驱动后只抽验了审批和个别档位，CodeBuddy Code 没有逐格跑。
- 原生能力接出来：审批（⏎ 允许、esc 拒绝）与提问、计划模式、`/` 命令、子 Agent、用量；附件（文件、图片、音频）按各家自己的输入方式发，模型收不了的在发出前拒绝。真机。
- 拒绝时可以附一句话（Claude Code、OpenCode），它按这句话换个做法；“拒绝并停止”直接结束这一轮（Codex、OpenCode）。真机（Claude Code、OpenCode）。
- 账号额度（Codex、Claude Code）：输入框下方一个圆环，悬停看每个窗口和重置时间。真机。
- 两轮之间保留原生进程，闲置 30 分钟释放；新对话默认勾上，可以关。真机：第二轮都复用了进程，Claude Code 13.1 秒到 2 秒，Codex 9.1 到 5.1，DeepSeek Harness 6 到 2，OpenCode 7 到 4，OpenClaw 4 到 2，Hermes 3 到 3。
- Codex 在你打字时就提前打开进程。真机：发送前 8.4 秒已经开好，第一轮 5.3 秒答完。
- 恢复、分叉、编辑并重发、重试。编辑并重发和重试在原生会话里退掉轮次，进程不换；DeepSeek Harness 由 Hub 带上历史开新会话。真机（2026-11-15，七家同一套四步：回词、再回词、把第二轮编辑重发、问它前面回过哪几个词）。
- 清空（单独输入 `/clear`、`/new`、`/reset`）由 Hub 接管：开一个新的原生会话。
- 速度档：Codex 用 `serviceTier`，Claude Code 用 `fast`（只有 Opus 一类模型有）。Codex 真机，Claude Code 的快档没真跑过。
- 回复流式显示，旁白和答复分段；刷新不丢、不重发；关掉页面不取消回复；结果未知的执行不会被自动重跑。
- 不设总量上限：回合没有时间墙（跑得久只提示），并行的对话不设固定个数，同一个目录里的几段对话可以同时干活（会提示）。

## 2. 多家协作

- **换一家接着做。** 新接手的一家拿到一份交接单：用户原话、每一家做了什么、改了哪些文件。预算是它窗口的一半，放得下就整段带；回到原来那家时只补它没看到的。真机。
- **委派。** 你从菜单发起，或者 Harness 自己调 `hub_delegate`，把一段活交给另一家。它在自己的子对话里做，用同一个工作区；结果自动告诉原对话；最多三层。读得了记录的一家，被委派时先拿到用户的原话和任务状态，做过的事要用再去读。真机：六家都当过发起方（2026-11-13，换驱动之前）；换驱动后各家都调通过 Hub 的工具，委派没有重跑。
- **任务上下文。** 一件任务是起头的对话，加上它委派出去的所有对话。
  - 任务板：目标、约束、决定。用 `hub_remember` 记，每条带编号、可以撤；变了以后，任务里每一家下一轮都会带上。
  - 记录目录 `<数据目录>/context/<任务>/`：每段对话每一轮的全文（原话、回复、每次工具调用的输入和输出、改动），只读，各家用自己的读文件工具读。读它不用你批：只读、路径都在这件任务的记录目录里的请求，Hub 在任何档位都代为允许。OpenClaw 的文件工具平时出不了所选文件夹，改用 Hub 命令读。真机（2026-11-15：CodeBuddy Code、Claude Code、OpenCode、Hermes）。
  - 状态块 `STATE.md`：目标、约束、做到哪、改过的文件、用户最近说的话，由 Hub 从记录里拼出来。在它接手或者压缩过之后，整块给它一遍。
  - 一轮进行中有了变化（任务板变了、原对话里用户又说了话、别的对话改了它碰过的文件），随它下一次调 Hub 工具的答复送到。
  - 别的对话改了文件会告诉它；委派的结果连同改动的文件和最后运行的命令，一起回到原对话。
- **压缩。** 由各家自己做。它一压缩，Hub 就把任务状态随下一次工具答复送回去。只有上一轮超出了窗口，或者原生会话找不回来了，Hub 才换一个新的原生会话接着做。按用量换会话默认关（`HARNESSHUB_RESEAT_AT`）。
- **进度。** 自己有任务清单的五家（Claude Code、Codex、Hermes、OpenClaw、CodeBuddy Code）用它们自己的，显示成计划。OpenCode、DeepSeek Harness 用 Hub 的 `hub_update_plan` 和 `hub_wrap_up`，显示在输入框上面和右侧栏，第一轮的小结可以顺带给对话起名。设置里可以改成都用或都不用。
- **Hub 的工具按需加载。** Claude Code、Codex、OpenCode、Hermes 自己按需加载；DeepSeek Harness 只列核心工具和 `hub_tool_search`，搜到的再补上。真机（2026-11-15）：Codex、Claude Code、OpenCode、DeepSeek Harness 都在要用时找到并调通了工具。
- 真机：[委派上下文尺子](../verification/delegation-ruler.md) 2026-11-14 按默认设置跑了一次（Claude Code + Haiku、DeepSeek Harness、Codex），换驱动后没有重跑。S1–S13 过；S14 带上 Claude Code 的提早压缩开关单独跑了一次，过；S15 里 Codex 过，Claude Code 撤掉了条目，但列了数据目录的上一层，按“越出工作区”判了不过。

## 3. 编码工作台

- 结束的一轮收成一行，下面一张改动卡（文件树、增减行数）。失败或被停下的一轮不收。
- 改动页：范围可以是本轮、这段对话、其他对话，或者 Git 范围（未提交的、相对默认分支或任一分支、某个提交）。能按文件夹看、并排看差异，点行号写评语，评语连同那几行放进输入框。
- 每段对话可以开自己的 Git 工作树（默认在 `~/HarnessHub/worktrees`，分支按标题起名）。每轮前后拍快照（`refs/harnesshub/checkpoints/…`，不动你的暂存区、HEAD 和分支）；“编辑并重发”时可以把文件还原到那一轮之前，只限对话自己的工作树。
- 提交、推送、建 PR（用你本机登录的 `gh`），都只在你点了才做。
- 终端：在对话的工作区里开你自己的登录 shell。收起或换对话不会断，回来先重放之前的输出；能分屏、分标签、跑 package.json 的脚本，选中的内容能放进输入框。
- 插话：一轮进行中再发的话插进这一轮。真机：七家各自的驱动上都插过（2026-11-15），页面上没有逐家点。
- 在编辑器里打开、在访达里显示、按标签读文件。
- 侧栏：按项目或按状态分组；置顶（可拖动排序）、稍后提醒、归档、最近删除（可恢复、可彻底删除）、多选批量操作、⌘Z 撤回、标为未读。别的对话等你处理时，标签页图标上带数字。
- ⌘K 搜所有对话的消息，⌘F 在对话里查找；命令面板；快捷键可以改；临时对话（不选文件夹，默认放在 `~/HarnessHub/chats`）；选文件夹用 macOS 自己的选择框。
- 真机：以上在试用服务上逐项点过，主要用 Claude Code + Haiku（2026-11-14）。建 PR 和推到真实的远端只有合成测试。

## 4. 管理本机的 Harness

- 只认官网方式的安装（npm、Homebrew、厂商脚本、uv），有几份就列几份。
- 安装、升级、卸载：先把命令列出来给你看；升级后按它自己的方式重启后台服务并核对；卸载只删程序，保留数据。真机（2026-10；2026-11-15 用它把 OpenClaw 从 2026.10.9 升到 2026.11.3）。
- 能力页：跨 Harness 统一管理技能、MCP、说明文件、子 Agent 和插件开关。只改用户级配置，写之前给出差异并留备份，可以撤回。真机（2026-10）。
- 能导入某一家自己在这个工作区里的原生会话。

## 数据和登录

- 都在 `--data-dir` 里：每个对话一个只追加的 JSONL 文件（`sessions/`），列表和翻页用可重建的索引；任务记录目录在 `context/`；工具详情与附件、管理、能力各一个 SQLite。
- 2026-11-12 起对话换了存法，旧格式的对话库 `gateway.sqlite` 不再读取，留在原处不动。
- 服务只监听 `127.0.0.1`，用启动时打印的一次性链接登录；有活动就续期，8 小时没有活动才失效。

## 没做

- WorkBuddy 应用本身：它的登录只交给自己的侧车，接不了，由 CodeBuddy Code 顶替。
- CodeBuddy Code 的提问和工具按需加载还没声明，页面没有逐屏看。
- Provider 统一管理：页面里是关着的，各家用自己配好的模型。
- 原生宿主池（[ADR-056](../decisions/0056-native-hosts-and-sessions.md)，一个进程服务多段对话）：现在是每段对话保留自己的原生进程。
- 上下文“按工作集少装”：量过，整段带过去只多等三四秒，先放着。
- 两轮之间由 Hub 请它先压缩一次。
- 委派还差三样：在父对话里停掉子对话、子对话做完时发系统通知、委派时选模型和档位。
- 打包分发：还没有发布版。终端用的 `node-pty` 要签名公证，`spawn-helper` 要保留执行权限；终端只在 Chromium 里试过。

## 原生做不到

- DeepSeek Harness：Web 宿主没有回退接口。退回 ACP 时没有插话、分叉和提问，沙箱在会话建立时就定了，中途改档只改得了 Hub 的答复。
- OpenClaw：只规划档下它拒绝一切命令，Hub 的工具用不了；改文件它从不来问（只在所选文件夹里改）。
- OpenCode、Hermes 没有沙箱：“自动执行”下，命令碰到工作区外拦不住（OpenCode 改工作区外的文件由 Hub 拒绝）。
- Hermes：普通命令它不来问，只规划档拦不住；它给 Hub 会话的这套工具里没有提问。
- Claude Code：它认为只读的命令（`ls`、`git status`）在“每步询问”档也不来问。
- CodeBuddy Code：没有原生分叉；手动压缩很慢（真机上只有一轮的会话压了 308 秒）；读到 EOF 不退出，Hub 被强杀时它的进程会留着。

## 只有合成测试，或没核对

- 建 PR、推到真实的远端；Claude Code 的快档。
- 超出窗口、原生会话找不回来之后换会话；原生回退中途失败后改由 Hub 带历史。
- 状态块不截断、`STATE.md` 在一轮中途刷新、经记录文件送达变化。
- DeepSeek Harness、Hermes、OpenClaw 压缩之后任务状态送回（它们的手动压缩本身真机过了）。
- 插话被拒、页面拿不准它收到没有；在归档的对话里发消息时自动取消归档。
- 消息搜索翻到第二页、⌘F 跳到还没读进来的早期轮次、相对默认分支的范围。
- 换驱动后各家没验的：
  - Claude Code：会话列表、Task 系列工具、旧版本的 CLI、额度用尽、登录失效。
  - Codex：MCP 询问、权限提升、它自己发起的回合、导入带改动。
  - OpenCode：子 Harness 嵌套、MCP 询问、它实验性的 todowrite。
  - OpenClaw：断线重连后补齐、插件审批、思考流。
  - Hermes：网关断开时进行中的一轮、断档后的补发。
  - DeepSeek Harness：同一个 `~/.dsh` 上同时跑两个宿主、能收图的模型。
- 全量的合成测试：有记录的最近一次是 2026-11-14（1,314 项，浏览器 114 项），换驱动后没有记录。
