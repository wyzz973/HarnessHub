# 第一阶段需求清单

生成自 plan/requirements.json；使用 python3 tools/check_design.py --write 更新。全部为待实现需求，来源为 user 或 derived，不表示代码已完成。

| ID | 需求 | 行为 | 来源 |
|---|---|---|---|
| R01 | 统一入口 | 用户仅向网关对话或发送命令；界面和程序接口共享语义 | user |
| R02 | 公共Session | 公共Session身份独立于Harness及原生会话 | user |
| R03 | 接入生命周期 | 可增加、排空、停用和移除Harness，并保留版本与历史 | user |
| R04 | 能力证据 | 安装、声明、观察、验证和平台能力分别表达 | derived |
| R05 | 自动分配 | 按任务约束、能力、版本化策略选择并解释候选 | user |
| R06 | 用户指定 | 允许指定Harness；不可用时明确失败，不静默换目标 | user |
| R07 | 持久输入 | 消息有序、幂等、可恢复，持久受理和执行分开 | derived |
| R08 | 上下文接续 | 有来源、预算和水位的公共上下文供新执行者接续 | user |
| R09 | 独立切换 | 同一Session可切Harness、Provider/模型，运行中请求有明确边界 | user |
| R10 | 模型资源独立 | Provider/模型与Harness独立，调用路径和目标可验证 | user |
| R11 | 执行生命周期 | Agent启动、执行、结果、停止、清理有明确责任 | derived |
| R12 | 权限与工具 | 实际选项、决定、送达、应用和工具结果分别记录 | derived |
| R13 | 期限与取消 | 总期限覆盖所有阶段，取消幂等，清理单独表达 | derived |
| R14 | 未知结果恢复 | 重启核对归属，未知副作用不自动重跑 | derived |
| R15 | 持久事件 | 可重放有界事件，断线不取消，慢客户端不阻塞执行 | derived |
| R16 | 结果与产物 | 执行、质量、文件完整性、模型证据和清理分别表达 | derived |
| R17 | 身份与秘密 | 执行/管理认证、所有权、最小秘密作用域和脱敏 | derived |
| R18 | 工作区归属 | 受管理工作区单写租约，切换前确认旧写者静止 | derived |
| R19 | 契约与版本 | schema、SDK、协议和持久格式各自版本化且可追溯 | user |
| R20 | 平台隔离边界 | POSIX与Windows能力分别设计验证，不虚构隔离 | derived |
| R21 | 择优证据 | 任务质量排名基于独立评测；证据不足时不声称最佳 | derived |
| R22 | 应用服务一致 | CLI/UI/SDK仅适配相同应用入口，不另建执行循环 | user |
| R23 | 原子工程任务 | 每项任务单一职责、唯一文件所有权、明确依赖和验收 | user |
| R24 | 全面可信测试 | 有效/无效/边界/竞态/故障/恢复/真实组合与平台分层覆盖 | user |
| R25 | 协议防腐 | ACP和原生协议独立适配，第三方类型不污染领域 | user |
| R26 | 有界可诊断运行 | 配置集中、队列与流有上限，日志与事件可定位失败 | derived |
