HarnessHub 统一协议

HarnessHub 定一套自己的协议。每家 Harness 的适配器把原生事件翻译成协议里的条目，界面只按协议显示，不认是哪一家。

1为什么要定协议

你试用的那个对话里换了五家 Harness。同一类东西，五家显示成五个样。下面是从那次对话的记录里直接取的。

同一件事DeepSeek HarnessOpenCodeClaude CodeCodex
执行一条命令bash，算“其他工具”shell命令本身/bin/zsh -lc 'npm test'
读一个文件read，看不出读了哪个路径路径没有这类条目
Hub 自己的工具——mcp__harnesshub__hub_turnsharnesshub.hub_read_turn
模型名["deepseek-official","deepseek-flash"]opencode/glm-5.3-flash-free不显示不显示
一轮的输入用量—20.8k4356.3k

根因在现在的公共契约。它有两个问题：

  • 工具调用只有标题、状态、类别三个字段，后两个是任意字符串。各家传什么，界面就显示什么。Hub 没有归一。
  • 一轮里的内容没有先后顺序。思考、工具、回复各存各的。界面只能把“过程”堆在上面、回复放在下面，还原不出“先说了一句、跑了命令、又说了一句”。

2设计原则

  1. 词汇表小而固定。界面只需要认识协议里的二十几种条目，不需要认识任何一家 Harness。
  2. 复杂留在适配器这一侧，并且归一规则只写一份。六家共用一个归一模块，各家只提供自己的差异表。
  3. 不认识的东西不丢。落进“其他工具”这个兜底条目，带着原生名字显示出来。
  4. 显示给用户的文字由 Hub 生成。原生文字只当数据，限长、过滤后才用。
  5. 生命周期类的条目由 Hub 产生。换家、停止、清空、错误在六家上完全一样。
  6. 界面读能力，不读名字。某家没有的功能，按它的能力声明隐藏，不写“如果是 Codex”。
  7. 不谎报。拿不到的数据标成“未知”或不显示，不填零，不猜。

5回合：状态、用量、计时

回合状态

排队中、准备中、进行中、等你处理、已完成、失败、已停止、结果未知。比现在多一个“等你处理”。

结束原因

原因界面说法
end_turn不显示（正常结束）
user_stopped你停止了这一轮
max_tokens输出达到上限，没有说完
max_steps步数达到上限
refusal模型拒绝了这个请求
budget超过了这一轮的时间上限
cleared已清空，下一条消息开新会话
error见这一轮的错误条目
unknown没有拿到结束原因

现在的问题是：模型拒绝、输出到上限这两种只显示“失败”，没有原因。

执行者

每个回合记下当时是谁在做：Harness、模型、思考强度、权限档位。模型统一成三样：原生编号、显示名、厂商。界面只显示显示名，例如“DeepSeek Flash”，不再出现 ["deepseek-official","deepseek-flash"]。

用量的统一口径

数字定义
输入这一轮里所有模型请求读入的全部内容之和，包含从缓存读的部分
其中缓存输入里从缓存读的那部分
输出这一轮生成的全部内容，包含思考
上下文占用这一轮结束时窗口用了多少、一共多大
费用只在 Harness 报了的时候有。标明是这一轮的还是整个对话累计的
完整程度完整、部分、没有。部分或没有时界面不显示数字，不填零

Claude Code 那个“输入 4”就是没把缓存部分算进去。按这个口径，适配器要自己加起来再上报。

计时

全部用 Hub 的时钟：受理、发出、第一个输出、结束。界面只显示“用时”。

6事件流

界面打开一个对话时先拿一份完整快照，之后只收增量事件。每个事件有递增的序号，断线后从上次的序号接着收。这套机制现在已经有，变的是事件的内容。

事件内容说明
条目更新一整条条目开始、进展、完成都发这一种，靠状态区分。同一编号后到的覆盖先到的
文字增量条目编号、追加的文字只用于回复和思考的流式输出
命令输出增量条目编号、追加的输出不落盘。只有展开了这条命令的界面才订阅
回合更新状态、结束原因、用量
对话更新标题、当前执行者、任务清单的最新一份
  • 大块内容（命令输出、差异、工具的输入输出）不随事件走，展开时才取。各家输出多少不会影响时间线的流畅。
  • 界面收到不认识的条目类型时，显示成一行“未识别的条目”，不跳过。

状态词表

各家的 inProgress、in_progress、success、declined、rejected、error 等，统一映射到第 4 节的八种。拿不到结果的记“结果未知”。现在 OpenClaw 补记的工具在没有结果时被记成“已完成”，这要改。

一致性测试

  • 把每家真实跑出来的原生输出录下来，回放给适配器，检查得到的条目序列。
  • 定一张场景清单：跑命令、读文件、改文件、搜索、联网、调 Hub 工具、任务清单、审批（允许和拒绝）、提问、出错、被停止、压缩、子任务。
  • 结果是一张“场景 × Harness”的表：通过，或者标明这家做不到（对应能力声明里的“无”）。
  • 你试用留下的那个对话有五家的真实记录，可以直接当第一批材料。

输入框旁的控件现在因 Harness 而异：权限选择器只有 Codex 有，药丸位有时是思考强度、有时是模式。协议定一套档位，各家映射到自己的原生选项。某家不支持的档位不显示，Hub 不去模仿。

思考强度

五档：关、低、中、高、最高。各家原生的 minimal、xhigh、ultra、adaptive 等映射到最近的一档，只显示这家支持的。

模型

一个选择器，先选 Harness 再选模型，显示名由 Hub 统一整理。其余原生选项放进“高级”，有中文名的用中文名。

10审批与提问

  • 要批的对象分类：命令、改文件、读文件、联网、工具、其他。界面按类别显示对象，例如等宽字体的命令。
  • 选项统一成四种角色：允许这一次、这个对话里都允许、以后都允许、拒绝。各家原生的选项按角色归位，归不了的保留原词。现在界面是靠正则猜哪个按钮是“始终允许”。
  • 留痕：审批和提问作为条目存下来，包括谁在何时选了什么。现在决定之后请求就被删除，刷新页面后看不到你批过什么。
  • 位置：等你处理时停靠在输入框上方，处理完变成时间线里的一行，例如“已允许：运行 npm test”。审批和提问用同一个位置。

11原生命令

  • 斜杠命令统一成一份目录：名字、说明、来源（Hub、Harness、技能）、对上下文的影响（保留、清空、压缩、回退、无、未知）。
  • 菜单分组显示。现在各家从 0 条到 223 条不等，混在一起不分组。
  • /clear 由 Hub 接管，在六家上行为一致：开一个新的原生会话。时间线上显示一条“新会话”分隔线。现在清空后只显示“已完成，没有文本输出”。

12上下文与 Harness 可用的工具

这部分沿用已经定下并做完第一片的设计：Hub 管全部上下文，换家时发一点，其余由 Harness 自己取。协议把它纳进来，并加两个面向界面的工具。

工具作用状态
看目录、读一轮、搜索Harness 读回对话里的任何内容已做，Claude Code 与 Codex 真机通过
更新任务清单写入或更新这一轮的任务清单新增
写小结回合结束时写两三句小结，可带一个问题和一两个选项新增
委派让另一家做子任务。第一版只给用户用以后

一份数据，两个用途。任务清单和小结显示在界面上，就是 Claude 桌面版那样的任务清单和“下一步”框。换家时带过去，就是之前设计的进展卡。Claude 桌面版的任务清单和章节，也是 Agent 调用宿主提供的工具来更新的，是同一个做法。

  • 原生就有计划功能的 Harness（Claude Code、Codex），它的计划直接进任务清单，不需要调 Hub 的工具。
  • 原生没有的，可以通过 Hub 的工具得到同样的任务清单。会不会主动调用取决于模型，没有时界面就不显示这一块。
  • 交接的状态（送达中、已确认、未确认）记在“换家”条目上，界面只在这一处显示。

规则

  • 按时间从上到下。中途的说明、动作、最终回答交错出现，是它实际发生的顺序。
  • 两段文字之间连续的动作合成一行摘要，默认折叠。只有一个动作时直接显示那一个。点开看每一条，再点开看输出或差异。
  • 摘要怎么写：最多列三类动作，其余写成“还有 N 个动作”。数的是不同的文件和命令，不是调用次数。一组只动了一个文件时写成“读取并修改了 cart.js”。有失败、被拦、被停止的，在后面标出来，例如“1 个失败”。
  • 详细程度两档：普通（折叠）和详细（全部展开）。
  • 不折叠的情形：正在进行的那一组；失败的动作；等你处理的审批。
  • 思考默认折成一行“思考了 N 秒”。没有思考内容的 Harness 不显示这一行。
  • 任务清单和“下一步”框在输入框上方，不在时间线里。回合进行中显示任务清单，最多 12 步，更多的折成“前面还有 N 步”“后面还有 N 步”。回合结束并且有小结时显示“下一步”框，任务清单收起。
  • “下一步”框：两三句小结，最多一个问题，一排按钮。第一个按钮是推荐的做法。
  • 换家只有一种分隔线：从谁到谁，加一句带了什么。现在有五种说法。交接的补充说明都收进这一行。
  • 每轮的脚注只有一种写法：Harness、模型、用时、输入、输出。拿不到的那一项不写。
  • 输入框上方最多一条提示。现在代码里同屏最多可以出现 15 类提示位，接力就占 5 类。

16存储与版本

  • 要改存储格式。有序的条目、审批和提问的留痕，现在的格式存不下。存储版本从 13 升到 14。
  • 旧对话不迁移内容。打开旧对话时按协议现算一遍来显示。它的先后顺序只能尽量还原，审批记录没有。
  • 按约定，改存储格式要写一份决定记录，并做一轮独立审查。这是我们留下的少数几条硬规矩之一。
  • 以后加东西只加不改。新增条目类型或字段时，旧界面把不认识的显示成“未识别的条目”，不出错。
  • 协议版本记为 hh/1。适配器声明自己按哪一版。

17分步落地

每一步都能在浏览器里用真实的 Harness 看到效果。

步做什么你会看到动存储吗

2有序条目落盘，界面按时间交错显示，连续动作分组折叠时间线变成 Claude 桌面版的结构升到 14

第 1 步不动存储，最快见效，你说的“乱”里最扎眼的那几项它都能解决。第 2 步是结构上最大的一步。

18已经定下的八件事

11 月 12 日，八项全部按下面每条的建议确定。

  1. 条目这 23 种，够不够，多不多？我的建议：就这些。少了会像 T3 那样有东西落不到合适的类型，多了界面要认的就多。
  2. 一轮里按时间交错显示，同意吗？这要改存储格式。我的建议：做。这是和 Claude 桌面版结构一致的前提，也是“乱”的第二大来源。
  3. 思考内容怎么显示？我的建议：默认折成“思考了 N 秒”，可以点开。和 Claude 桌面版一致。
  4. 权限五档、思考强度五档的名字和划分，可以吗？见第 9 节。Hub 不模仿某家没有的档位。
  5. 视觉向 Claude 桌面版对齐到什么程度？我的建议：结构、密度、字号、间距、圆角都对齐，取代设计语言 2.0。它的 Code 界面强调色本身是蓝色，和我们的接近，继续用我们的蓝。图标和应用名保持我们自己的，字体用系统字体。
  6. 旧对话只在打开时现算，不迁移内容，可以吗？我的建议：可以。4317 上的旧对话照常能看，只是没有新的细节。
  7. “只发这条消息”还留不留？你试用时有一条消息是这样发出的，导致 Claude Code 没拿到 Hermes 那一轮。如果那次不是有意的，我建议把它从输入框旁拿掉，收进菜单。
  8. “本轮改了哪些文件”由 Hub 自己记，还是用各家报的？DeepSeek Harness、Hermes、OpenClaw 不报差异。我的建议：Hub 在每轮前后各记一次工作区的状态，自己算出改动，六家就都有了。T3 Code 也是这么做的。这一项可以放到第 2 步之后。
