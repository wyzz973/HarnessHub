## 2. 各方案共同或各自的致命缺陷（终稿必须避开）

1. **原生位置与送达水位必须分开**（J1）。`throughRunId` 现在同时承担两个用途：精确分支（`runtime.ts:438`）与配置承接（`state.ts:392`、`carriedNativeConfiguration`）。P1、P3、P4 的 P0 都直接拿它当送达水位，会把这两处一起改坏。
2. **“命令回合不推进”不能照字面执行**（J1）。照字面执行的话，单 Harness 对话里 `/compact` 之后的下一条也会被包上信封。本绑定自己执行过的 Run，原生会话天然已知（P3 的 executedOn）；水位只覆盖外来事实。
3. **用户主动清空必须按原生语义处理**（J3，P1、P3、P4 都犯了）。`/clear` 之后不得自动灌回完整交接单，连本 Harness 清空之前的轮次也不行，否则单 Harness 用户在 Hub 里永远得不到空白上下文。正确做法：nativeEpoch 加 1，水位记为 `basis: user_cleared`，输入框上方显示一行提示，用户可以一键附上之前的对话。
4. **标记缺失时不能自动新开原生会话**（J1、J3，P3、P4 都犯了）。Hermes 压缩后回放中没有旧行，会造成误判，进而丢掉 A 自己的原生上下文。先用压缩证据分类：确认压缩过，就发重锚包加未送达的增量；否则由用户选择，默认在同一会话补发完整交接单。
5. **从未交接过的会话一个字节都不注入**（J3 M1）。P1 在任何压缩之后都发重锚包，还会发回合外改动通知，在单 Harness 会话里也会注入，而且这些注入用户看不到。
6. **秘密**（J4）：
   - 不得把秘密值未加盐的 SHA-256 写进事件（P1）；标签改用按安装生成密钥的 HMAC。
   - Hub 转交给 Harness 的环境凭据、受管 Provider 的秘密，在出境时都要做原值、JSON 转义、URL 编码三种形式的精确匹配替换，所有方案都缺这一条。
   - `RedactedHarnessControl` 在生产中并不启用，不能宣称已覆盖 INV-17（P2、P4 误称）。
7. **MCP 进程所有权**（J1、J2、J4）：
   - P3 的 Hermes shim 由用户网关持有，Hub 没有可等待的关闭入口，违反 INV-26。
   - shim 可执行文件放在可被沙箱内 Harness 改写的数据根下，会构成跨 Harness 的沙箱逃逸。
8. **同意按目的厂商记录，不按目标 Harness 记录**（J4）。在第一次携带接力内容的发送处内联询问，不放在选择器里（ADR-015 规定直接切换）。不要每个对话都重新询问（J3）。

## 3. C1–C10 裁定

除 C7 的一处分歧外，四位评审的意见都一致。

| 编号 | 裁定 |
|---|---|
| C1 默认保真度 | **默认用确定性分层投影**，以下内容逐字保留：用户原话（优先级最高）、失败证据、最近一轮回复（≤8 KiB 时照录，更长则保留首 2 KiB 与尾 6 KiB）。**整段叙述化历史放得进默认档时就全部照录**（P2 的叙述化规则）。保真档（P2，约 16k）与完整档（≤32k）只能由用户显式选择。不按交接方向调整，失败后也不自动降档 |
| C2 预算 | **只有一个策略解析器**。默认档 T ≤ min(8k, 窗口 5%, 价格悬崖余量, 1.5 s × 实测预填充速率, $0.20/π)，其中费用与时延上限只能调低档位，不能调高。必含块 ≤3k；标准档中用户角色里的模型与工具文本 ≤3k token（J4 M8）；精简档约 4k；只交目标约 2–2.5k；增量默认 ≤1.5k；重锚包 ≤600，每次压缩最多一次，并且只发给本纪元收到过交接单的绑定。超出最小交接单时，在启动程序之前失败（K8） |
| C3 布局 | 两段 text，不用 resource。**第一段的首行是用户原话前 ≤200 字**，照顾原生标题与预览；交接单 ID 与框架都不放在首行；送达标记放在第一段（供 E2 核对）。用户原话全文作为最后一段 text，首尾都写明只有最后一段是指令。交接单 ID 在模型可见文本中只出现首尾两处，不出现 seq、版本与指纹 |
| C4 写入时机 | **权威接力状态与所属提交放在同一事务**，包括送达判定、水位与交接单；每个 Run 的派生小记录随 `run.ended` 提交，出错时隔离、标为落后，不让 `run.ended` 失败。重活放在事务外：工作区观测、diff 解析、大扫描。可重建的大派生物可以异步生成，但派发前要有限时屏障 |
| C5 复述 | **默认不复述**。框架写明“不需要向用户复述”；把首个回复的元话语率 ≤10% 纳入验收；复述只作 HH-RelayBench 的对照臂 |
| C6 推拉 | **v1 只推送，推送部分必须自足**，并附如实的省略账目。v1.1：文件视图，前提是数据根与工作区按 realpath 互不包含，且该 Driver 读取外部路径免审批的探针已通过。v1.2：零凭据 stdio MCP，前提是 Hub 能监督其进程组、工具列表在建会话时固定、探针通过。永不用回环 HTTP 加 bearer；Hermes 永不挂 MCP；Claude 的 additionalDirectories 在探针通过之前不用 |
| C7 返回 A | **默认原生续接加增量**，配“X 离开期间”卡片，并在开销小的地方核对标记链（只认客户端写入的用户条目）。标记缺失的处理见第 2 节第 4 条，**永不自动新开会话**。缓存已冷且原生上下文很长时，并列显示两种方式的首个请求费用与之后每个请求的持续费用，由用户选择。J4 主张发现分叉就新开会话，这里不采纳，理由是会误伤压缩后的会话 |
| C8 交出方说明 | 默认关闭，由用户显式发起，作为 A 上一个可见的普通回合，请求文字可见、可编辑，≤800–1,200 token，先显示估算的时间与费用。永远不在 fork 副本里写，也不在切换路径上写 |
| C9 决定的来源 | 权威内容只来自三处：用户钉住、Hub 记录的批准或拒绝（只作历史，不跨 Harness 继承）、用户原话。Harness 自述只能作为带“自述，未核实”标注的引文出现。词表只用于在必须省略时挑选保留哪些用户原句，不生成新的“决定”句 |
| C10 改动事实 | git 只在交接回合（以及返回 A 的同步核对）观测一次，与启动并行，硬上限 250 ms。子进程只带白名单环境，参数加 `-c core.fsmonitor=false --no-ext-diff --no-textconv`，超时后杀掉整个进程组并等待退出，观测结果作为事实持久化。归属用工具事实加“Run 结束后 mtime 有变化”判断，只写“第 k 轮期间”或“轮次之间”。非 git 工作区做有界 lstat 扫描，超限记为“未核验”。界面写“未归属的改动（可能来自你的编辑器）”，不当作告警。凭据类路径的 diff 永不出境 |
