# 第一轮小结与第二轮任务（主负责人）

日期：2026-11-03。第一轮 Workflow `wf_80c957ad-f44`：7 路调研（R1–R7）与覆盖审查，补调研两份（R8 送达证据、R9 跨 Harness 外部证据与评测设施）。各报告在 [round1/](round1/)，机械汇编见 [round1/00-digest.md](round1/00-digest.md)。本文件只写三类内容：已形成的共识、补调研裁定的事实、仍有分歧并需要第二轮表态的问题。

## A. 共识基线

第二轮各方案以下列各条为起点。要推翻其中任何一条，须给出新证据或第一轮遗漏的反例。

1. **载体只用公共事实**。跨厂商交接只以 Hub 自己的公共事实为载体：不读写其他 Harness 的私有会话存储，也不搬运不透明的原生压缩状态或 thinking（R1、R3、R5、R9）。
2. **事实是数据，文本是渲染**。交接单由结构化公共事实确定性渲染，切换路径上不调用模型。模型写的叙述只作可选旁路，并标注作者（R1 D1、R2、R3、R6、R7）。
3. **原文永远保留**。派生层（工作账本、交接单）只追加、可重建，每条都带来源、水位、内容指纹与策略版本（INV-13、INV-22）。修改表现为“取代”，不整体重写：ACE 观测到整体重写会让上下文坍塌（R2）。
4. **分层而不截断**。分为常驻层（L0）、近期原文（L1）、按需取回（L2）三层。超限时显式省略，并附省略账目（类别、计数、序号范围、取回方法），不静默截断。完整历史超限不再报 `CONTEXT_TOO_LARGE`，改为分层降级。
5. **外来工具调用叙述化**。用陈述句重述外来工具调用，命令、路径、退出码和错误摘录逐字保留，原生工具名只作归属注记，不伪造原生工具结构。依据是 Codex `/import` 与 zen 的一手实现，以及 DCAS 与 Interface-Induced Censoring 的格式不匹配证据（R9）。
6. **框架措辞**。只有当前用户输入是指令；历史是数据，放进不可信数据块并转义；历史中的批准不跨 Harness 继承。未完成项写成过去时的快照，不用祈使语气，避免旧任务复活与范围扩张（Hermes #41607、#38364）。同时写明工具照常可用，避免“仅供参考”压制工具调用（Hermes #65848）。
7. **水位拆分**。分为 dispatched 与 delivered 两个水位。只有正面送达证据才推进 delivered；命令回合与 Driver 合成的结果不推进（R4、R8）。
8. **注入一次、只追加**。交接单只在换人后的第一回合注入。A→B→A 只追加增量，不在每回合重注入状态块（重注入的成本是二次方，R6）。同一输入渲染出的字节必须确定，开头不放时间戳或随机 ID。
9. **系统层只放静态协议**。如果使用系统层通道，只放跨会话逐字节相同的静态接力协议，交接内容不进系统层（R5 D2、R1 D11）。Claude 的系统提示与 Codex 的 developer instructions 都在建会话时冻结。
10. **不动用户配置与工作区**。不改用户全局配置。Hub 自有目录放在工作区外，不在工作区内建隐藏目录（R5 D6、D7）。
11. **质量证据**。用行为指标与确定性判定评估质量，不用模型自评，为此建 HH-RelayBench（R2、R6、R9）。Harbor 可用于离线校准内容策略，但不能代替 HH 自己的通道与水位的真机验收。
12. **前置修复**。去掉每个回合对完整历史的预算（`runtime.ts:1334`；切换校验 `:1570` 同理），只对将要发送的内容做预算。正式运行时已实测，快照到约 1.5 MiB 时续接停摆（R4、R6）。

## B. 补调研裁定的事实（R8、R9）

- **写入时机**。六家都在第一次模型请求之前把输入写进原生历史，所以 Provider 拒绝、超窗、限流都不丢输入。让水位失真的是另外四种情形：插入前的接口拒绝（如 Codex `input_too_large`）、Driver 合成的“未发送”结果（如 OpenClaw `model_not_applied`）、插入前的取消，以及清空或回退类原生命令。
- **送达证据分三级**：E1 实时事件、E2 事后核对、E3 Driver 结算推断。没有证据时记为 unknown，不记为 not_recorded。Driver 能力声明里不出现产品名（R8 的 `delivery{live, verify, successProvesRecorded, unlistedSlash}` 与命令目录 `contextEffect`）。
- **Hub 已收到却丢弃的证据**：Codex 的 `userMessage` 条目（`codex.ts:706`）与 `clientUserMessageId`；Hermes 在 `session/load` 时回放的 `user_message_chunk`；OpenClaw 回读转录时的 user 行。
- **清空与回退命令真实存在**：Hermes `/reset /undo /retry`，OpenClaw `/new /reset`，Claude `/clear`（Hub 在没有新增来源时会原样发送它）。原生命令必须声明 `contextEffect`，R4 D18 应从 P3 升为 P1。
- **叙述化有一手工程佐证，跨厂商续做质量没有公开实验**。Codex `/import` 与 zen 都把外来工具调用写成带标记的文字；Harbor 的 ATIF 加载和 session-migrate 只验证到“能加载”。但跨厂商续做质量至今没有公开实验。AgentBaton（跨厂商模型，同一脚手架）：弱→强时把历史放进日志文件让接手方去读，优于塞进上下文，也更便宜；强→弱时放进上下文常更好。
- **在编辑未完成处切换代价高**。Fail-Fast/Restart-Smart：在编辑未完成处切断，误杀率 18.8%，等编辑完成再切为 8.8%，所以切换边界宜在回合结束。中断时的 diff 作为覆盖层，结果优于冷重启。
- **原生结构的局限**。ACP v2 的“受理”等于插入，但不等于持久化；OpenCode 的 synthetic 在 `session/load` 回放时不出现，无法事后核对。claude-agent-acp 0.99.1 把 resource 块追加到整条消息末尾（`acp-agent.js:10358`）。

## D. 不要再引用的弱结论（覆盖审查核对过原文）

- **HSC-Bench 的“18 对 12”**：这是全部工具类任务的同目标重复次数。在两种视图都明确保留了完成记录的 19 题子集里，114 次结构化接续只有 2 次重复。“记录了不等于会照做”有证据，但量级被夸大了。
- **HSC-Bench 与 Handoff Debt**：只证明“结构化优于叙述”，不能证明“无模型的确定性投影就够用”。两者的结构化状态都由模型生成。
- **方向感知策略**：只有同族或小模型的证据，每种配置只跑一次，没有跨族结果，只宜作可选参数，不宜作默认。
- **R5 的通道矩阵**：全部没有真机证据。**R6 的费用与时延表**只说明量级，不宜直接写成验收目标。
- **Amp 的 Handoff**：已于 2026-05-06 取消，以 R1 为准。**Handoff Tax**：两种 Compact 都压缩完整前缀，区别只在由谁来写；引用数字时注明表号。

## F. 第二轮安排

- **方案（4 个，独立出稿，各押一个不同的核心赌注）**：P1 账本优先；P2 原文保真优先；P3 推小拉大；P4 控制面与原生通道优先。每个方案都必须完整回答 Q1–Q11，走查 S1–S16，给出数据模型、事件、v13 存储、七家逐家的交付计划、失败语义、性能目标、界面时刻、测试与迁移，并对 C1–C10 逐条表态，最后写自我批判。
