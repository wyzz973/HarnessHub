# 文档规范

文档服务于实现、使用与验证，中文为主要语言。规则来源与裁剪理由见 [治理决策](decisions/0001-development-governance.md)。不为尚不存在的功能编写看似可用的运行说明。

## 文档归属

| 位置 | 唯一负责的内容 |
|---|---|
| 根 `AGENTS.md` | 每次任务需要的短规则及详细文档链接 |
| 根 `README.md` | 项目状态、实际启动方式与开发入口 |
| `DESIGN.md` | 已采纳的架构、模块职责和产品运行语义 |
| 根 `TODO.md` | 开发任务、前置依赖、进度和每项验收证据 |
| 本目录的 development/testing/documentation | 实现方式、验证方法和文档治理 |
| 未来模块 README / API 参考 | 所属配置、使用方式、错误、限制和兼容要求 |
| 源码接口及 JSDoc | 精确类型与调用契约 |
| `docs/decisions` | 重要决定的理由、真实替代方案和代价 |
| 验收记录 | 指定版本、环境与实际执行证据 |
| 原提案与源码调研 | 研究输入和历史依据，不覆盖当前 DESIGN |

每条事实只有一个权威位置，其他文档用相对 Markdown 链接引用。目录说明只描述子模块用途，详细契约写在所属模块。无需为每个小目录建立 AGENTS 或 README。

教程按前置条件 → 操作 → 预期结果 → 验证和恢复组织；参考文档按查阅对象描述行为，不混入开发流水账。新文档进入 [索引](README.md)。

## 与代码同步

行为、默认值、错误、权限、取消、数据格式、公开类型或命令发生变化，同次更新所属文档与使用方。机械格式调整、拼写或不改变契约的私有实现无需虚构文档改动，交付说明其不影响公开行为即可。

架构、跨模块接口、持久化/wire/config 格式、安全边界或重要依赖取舍新增或更新 ADR。其他非机械变更在提交/PR或任务交付中说明问题、最终行为和验证，避免为每个 bug 创建重复决策文档。

决策状态与实现状态分别管理：ADR `accepted` 只表示采用方案；实现完成及测试证据由验收记录承担。已被替代的提案保留显式链接，不能继续被写成现行命令或功能。

## JSDoc 与示例

公开导出、Driver SPI、API/IPC 消息和 Store 接口写清：谁调用、输入限制、结果、可预期失败、取消/超时、顺序、幂等性与资源所有权。函数参数和非 void 返回值解释非显然含义；私有简单辅助函数无需逐行注释。不要写推理过程、测试复盘或重复代码。

TypeScript 类型只有一个定义。文档优先链接声明；需要复制时建立生成或等价检查，不能靠手抄长期维护两份 schema。HTTP/IPC 文档与 JSON Schema 的字段、默认值和错误保持一致。

可运行示例放入实际 `examples` 或测试 fixture，由类型检查及相应 smoke 覆盖，文档链接这些文件。未实现的接口示意须在代码块前标明“伪代码/设计示意，不可直接运行”；类型检查通过也不能代替执行证据。

运行命令必须能在说明的目录和前置环境执行，并给出成功判据。未创建的脚本只在计划检查表中命名，不能标“可运行”。源码入口与编译产物入口分别说明。

## 写作与链接

使用 UTF-8 无 BOM、LF、结尾恰好一个换行。一个自然段使用一行物理文本，编辑器软换行；代码块、列表和表格保留结构。Markdown 的长段落不能通过机械压缩隐藏多条不同规则。

写清具体对象、行为和后果，保留必要的失败与限制。避免“完善、稳定、生产级、全链路通过”等没有范围和证据的判断，也不按任意行数或英文词数砍掉契约内容。

仓库内文件使用相对 Markdown 链接；路径有空格使用尖括号。当前简易检查只验证显式行内文件链接，避免在正式说明中用它不能覆盖的定义式链接承担关键引用。计划文件使用代码文本描述；不要创建死链接。引用同仓库标题时使用实际标题锚点并人工核对。

公开源码证据优先固定 commit 链接，附阅读日期或版本；外部 AGENTS 和技能只是调研材料。生成文件或区域只能通过对应生成器更新，生成器和 freshness 检查同次维护。

## 自动检查与人工审查

已有 [文档检查脚本](../scripts/check-docs.mjs) 检查项目 Markdown 的 UTF-8/BOM/换行、代码围栏闭合，以及代码区域外显式行内本地链接的文件存在性与根目录范围。无 Markdown、无效内容或错误链接应以非零退出；[检查脚本测试](../scripts/check-docs.test.mjs)用临时项目验证接受与拒绝行为。

当前检查不验证 HTTPS 可用性、页内/跨页标题锚点、定义式链接、autolink/HTML、完整 CommonMark 容器语法、Mermaid 渲染或 TS 示例编译。四空格或 tab 缩进行会按代码示例跳过；关键文件链接应写成未缩进段落或普通一级列表，嵌套列表及引用块中的链接需要人工复核。上述范围通过人工复核及后续工具链接入，不能把脚本通过称为“所有文档正确”。暂不引入完整文档站点或检查调度器。

新增检查先考虑成熟解析器，避免逐渐把当前轻量脚本扩展成自制 Markdown 解析器。每条自动规则具有无效 fixture，文档说明它实际保证的范围；未接入的规则保留人工审查责任。
