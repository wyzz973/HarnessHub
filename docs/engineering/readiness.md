# 设计就绪与开始开发的门禁

更新：2026-10-09。当前状态：研究与设计评审。应用实现没有开始。

## 已具备的材料

产品范围和统一入口；主来源协议与固定仓库快照；DDD 语言/上下文/聚合责任；主要运行与交接契约；路由证据和安全边界；原子任务 DAG/所有权；需求-测试追溯；AI 工程工作流与实际设计检查。

这些材料可以评审，不等于已经“准备好开始全部业务编码”。结构检查通过只说明资料结构一致。

## 开始应用实现前必须关闭的设计问题

| ID | 问题 | 关闭证据 | 当前 |
|---|---|---|---|
| D-01 | OpenCode ACP 与 Codex App Server 的实际接入版本、模型配置、权限与停止能力 | 固定发行二进制/SDK与 schema；受控 probe 报告，不使用用户真实配置 | 未验证 |
| D-02 | 公共 Session/Turn/Attempt、ExecutionGrant、controlSeq 与消息/outbox 的精确 schema 和错误码 | 单一 schema、有效/无效样例、取消先于旧启动/控制重排场景与独立评审 | 设计建议，待冻结 |
| D-03 | busy switch 默认 wait_current 还是 cancel_current，失败恢复与并发请求 | 场景评审、转换表、模型性质/竞态用例设计 | 建议 wait_current，待契约评审冻结 |
| D-04 | ContextManifest 初版取材、大小/保留、原生绑定复用与水位规则 | 两个目标 Harness 的可导入材料、边界样例与能力报告 | 待验证 |
| D-05 | 首发平台、进程监督、OS owner 排他锁与 fencing 能力 | 各平台 owner 暂停/锁异常/进程身份/残留测试；不得仅按TTL接管；发行前原生证据 | 设计覆盖三平台，尚无新验收 |
| D-06 | Node patch、SDK/HTTP/SQLite/生成器版本与许可 | 安装、兼容、版本/许可证锁定；可重复工具链报告 | 候选未安装 |
| D-07 | 自动路由的质量声明与基线 | G1 前冻结规则、评测方案与无质量证据时的文案限制；宣称质量择优前取得真实保留集结果与不确定性 | 方案待冻结，质量未实测 |

设计评审通过后先进行独立、受控的协议/工具链验证，再冻结相关决定；不能用一个大“框架搭建”任务把这些未决问题藏进代码。受控验证是否执行与应用实现分开记录。

实施顺序明确为：V001–V007 受控验证与语义评审 → C001–C010 精确 schema/端口/OpenAPI 及有效无效样例冻结 → V008 独立就绪评审 → G001 起的应用实现。C 任务是设计交付，不依赖 G1 以后的实现代码；G 类型任务只消费/生成这些契约，不重新定义它们，避免“先实现再冻结”的门禁循环。

任务 ID 不是执行顺序，实际按依赖拓扑推进。静态边界检查 G063 在公共端口实现前接入；实际能力 probe G013 在具体 Adapter 可用后验收；Adapter 自身先做协议级验证，正式 G059 入口的双 Harness 验收集中在 G060；CLI/UI 的完整入口测试也依赖 G059。

相关 ADR 的独立文件由所属 C 任务交付，V008 独占索引维护和就绪核对；核心 ADR 的接受状态、验证引用或独立记录缺失时 G1 继续关闭。此项不是当前结构检查能够替代的语义评审。

## 后续实现门禁

- G0：资料、来源、任务与场景可追溯；独立评审无未报告严重矛盾。
- G1：关键能力与工具链验证，相关 ADR/契约冻结。
- G2：领域、数据与协议性质/集成测试通过，失败样例能被拒绝。
- G3：合成完整入口链路通过；数据库/IPC/进程保持真实。
- G4：真实双 Harness/双 Provider 的 Session 接续、路由和控制通过。
- G5：各发行平台、容量、安全与恢复通过。

没有测试代码或没有宿主时写 planned/未验证，不写 passed。用户要求先准备再开发，G1 之前保持应用实现门禁关闭。
