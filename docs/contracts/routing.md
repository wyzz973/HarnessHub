# 自动选择与路由证据

状态：proposed。自动选择是核心领域能力，但不能以主观分数证明“最佳”。

## 输入与模式

输入包含用户指定或 auto、任务类别（显式标签或已版本化分类结果）、所需工具/权限/环境、上下文预算、Provider/模型约束、执行预算与候选快照。

指定模式只校验该目标；不满足时拒绝，不能换另一个。auto 模式先过滤，再排序，固定结果形成 RoutingDecision。默认用户无需看 Harness 列表；详情可解释所选与原因。

## 硬约束

enabled 且不处于 drain/remove；固定安装与 Adapter 可用；协议版本兼容；平台与 workspace 权限满足；所需工具/权限和停止能力足够；上下文可以导入；模型组合支持；预算和并发准入允许。证据不足的必需能力视为不满足。

候选不足时 NO_ELIGIBLE_HARNESS，返回安全的排除类别和可操作建议。不能因为“所有 Harness 都差不多”跳过能力过滤。

## 排序策略建议

第一版规则式、确定性、版本化：硬约束后按照管理员为任务类别设置的偏好、当前可用容量、匹配版本的已验证可靠性，以及独立评测数据排序；并列有稳定 tie-breaker。质量未知时记录 unknown；不可把未知费用或成功率补零以影响分数。

自然语言分类器、学习型排名、自动在线探索延后。需要模型做分类时单独记录模型调用、预算、输入边界与不确定性；分类不能产生新的用户命令或绕过权限。

## 决策记录

decisionId、输入特征来源、策略版本、候选 descriptor/revision/证据指纹、排除理由、排序项及来源、所选 Harness/模型、决定时间、准入复核结果。

决策可离线复放；热更新不会重写过去理由。派发前候选不可用时本次明确失败或生成一个新的 auto 决策，不把新目标写成旧决策；未知执行后不自动换 Harness 重跑。

## 证明质量

评测集固定任务、模型、预算、工具与环境，按 task family 分层，训练/调参和保留集分开，记录重复次数、随机性、置信区间和失败归因。比较规则路由、固定默认和质量排名，不能用执行 completed 作为正确率。

第一阶段没有实测前，产品文案采用“按能力与策略自动分配”。“此时最佳”是目标，需后续真实任务证据支持。
