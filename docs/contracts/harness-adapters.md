## 权限档位各家的例外

- **Claude Code**：它认为只读的命令（`ls`、`git status`、`date`）在“每步询问”“自动改文件”下也不来问。只规划时它请求退出计划模式，由 Hub 拒绝，计划当作这一轮的回答。
- **Codex**：“自动改文件”和“每步询问”一样用 untrusted，改文件由 Hub 允许，命令交给你。“自动执行”是 on-request 加它自己的自动审查；没有自动审查的版本会来问，由 Hub 允许。恢复的线程离开只规划时，协作模式设回 default。
- **OpenCode**：没有沙箱。“自动执行”下工作区内都不问；要改工作区外的文件由 Hub 拒绝，它接着做别的；命令碰到工作区外照样放行。“本次会话允许”写成会话规则，不用它会写进项目库的 always。企业托管的设置压过会话规则。
- **DeepSeek Harness**：只在越出沙箱写文件时来问，不写文件的命令（包括联网的）从不问。只规划、每步询问、自动改文件用 read-only，自动执行用 workspace-write，完全放行用 danger-full-access。
- **Hermes**：没有沙箱，也没有只读模式。普通命令和 `execute_code` 从不来问，只规划档拦不住它们；敏感路径和说明文件的改动总是问；它自己的硬性拦截和你配置的 `approvals.deny` 一直生效。新会话先按“改文件都问”开出来，别的档在开会话后再改；yolo 只在开会话时能打开。
- **OpenClaw**：改文件从不来问；除完全放行外，文件工具只在所选文件夹里。压缩、回退和完全放行要 `operator.admin`。
- **CodeBuddy Code**：没选档位时用它自己的默认模式。它的 `auto` 和 `dontAsk` 模式不用，因为它们会在 Hub 的档位允许的地方拒绝。

## 档位由服务端落实

对话的选择里只带 Hub 自己的键：`hub_permission`（权限档）和 `hub_effort`（思考档），页面和 API 都不拼原生值。驱动拿到这一家的目录（会话报的原生选项、所选模型的选项）后，按声明解析出该档的原生值并设上（`levelOptions`，`src/contracts/flavor.ts`）。

- 档位键在，就以档位为准，压过同一选项的原生值。不带档位键就是“跟随这家自己的设置”。
- 恢复的会话按声明的 `neutral` 撤销上一档设的模式（Codex 的协作模式、OpenCode 的代理）。
- 思考档按所用模型就近解析，模型变了重新解析。
- 页面上直接改某个档位管的原生选项，就离开档位（显示“自定义”），按所选原生值运行。
- 对话换到另一家时，页面把同一档位带过去，由新一家的声明落实；没有这一档思考强度时就近，并提示。

逐家逐档的真机核对：`pnpm test:real:levels`（`tests/real/levels.real.ts`，证据只留类型、状态与大小）。

## Hub 策略的答复规则

`HUB_POLICIES`：读、搜索、思考类请求一律允许，不问用户；提问永远交给用户；没选档位时全部交给用户。请求属于哪一类，依次看：请求自带的工具类别、请求所指那次调用的类别、请求的标题、那次调用在 Hub 里的条目（命令、改文件、读文件，或工具名）。

- 各家的声明可以在某一档改掉其中一格，见上一节和声明文件。
