# Driver 接力适配阶段一（G069）的合成验证（2026-11-09）

对象是 [ADR-055](../decisions/0055-relay-and-context-scheduling.md) 的 G069 阶段一：六家 Driver 的静态 `RelayCapabilities` 声明、命令解析收敛到一个来源、端点层解析与厂商键、模型键。范围见[终稿](../proposals/relay/relay-architecture.md)第 3.2、7.4、8.1、10.4、17 节与 `plan/tasks.json` 的 G069 条目；取舍、偏离、待探针清单与需裁定的点写在 ADR-055 实施补记的“G069（阶段一）”一节。阶段二（`TurnText` 放置与首行省略、`deliveryPosition`、`verifyDelivered`、`input_recorded`、`BackendResult.native`、`userTextOf`、`setTitle`、`NativeUsage.requests`）不在本记录内。

**证据等级**：代码完成，合成测试通过。没有运行任何真实 Harness，没有碰 4317 服务、任何 `data/` 目录与用户的 Harness 配置与登录；没有调用模型、没有用凭据；只在 macOS 上运行（ADR-044）。声明里的 `probed` 全部为 false，没有任何探针（P2、P3、P6、P11、P14）在真机上跑过；读取真实配置文件的行为只在代码里，测试一律用 `os.tmpdir()` 下的合成家目录与工作区。Runtime 与协调器还不读声明，读端点的函数还没有调用方；审查后的修正里有三处有意的行为变化（dsh 的读法、名叫 Object 成员的命令的效果、目录缓存保留命令效果），见下文“审查后的修正”。

## 没有验证的

- 真实 Harness：六家的任何一格都没有真机证据，`probed` 全部为 false；端点层的顺序（Q24）、Claude Code 设置里的 `env` 是否盖过进程环境、OpenCode 与 OpenClaw 的端点键路径、Ollama `*-cloud` 的命名，都只按产品文档与源码推断，由 G074 的 P14 核实。dsh 的层序按本机安装包 0.2.1-rc.5 的源码只读核对过，但没有运行 dsh；它的插件配置 `baseURL` 与 pi-ai 路由不读，厂商键只在已读的层里准确。
- 执行路径：Runtime、协调器与 Driver 的 `open()` 都还不读声明、不调 `readEndpoint`；声明在受理时的作用（探针门控、命令预分类、同意）要到 G072。
- 设计检查：两个新源文件属 G069 的 `owns`，但 relay 切片的 `allowed_files` 没有列它们，`check:design` 报两行 `application source outside approved slice`，按简报不改 `plan/`，由主负责人集成时登记；`plan/test-cases.json` 里 G069 的用例仍是 planned，G069-D01–D04 没有计划条目。
- Hermes 的端点：没有读任何键（第 8.1 节没有点名），Hermes 的厂商键阶段一恒为 `unknown:hermes`。

## 审查后的修正（2026-11-09）

独立审查认为没有阻断项，提出两条重要、若干条次要。每条都先在本机复现再改，处置与理由写在 ADR-055 实施补记的 G069 一节。**证据等级仍是：代码完成，合成测试通过。** dsh 的层序按本机安装包源码只读核对（`@deepseek-ai/dsh` 0.2.1-rc.5 的 dsh-llm-deepseek、dsh-launch-environment、dsh-credentials-local、dsh-app-boot），没有运行 dsh。

**复现**：
- dsh：`readEndpoint("dsh")` 读 `$DSH_HOME/.credentials.yaml` 的顶层 `DEEPSEEK_BASE_URL`。源码里基础地址取 `config.baseURL ?? launchEnvironment.get("DEEPSEEK_BASE_URL")`，启动环境只有 process、项目 `.env`、家目录 `.env` 三层，凭据文档（`version: 1`、`refs`、`records`）不参与；rc.5 的 `--profile` 启动还会因为任一 `.env` 设了 `DEEPSEEK_BASE_URL` 而拒绝启动。审查建议的“凭据文档最先”是凭据引用的优先级，不适用于基础地址，所以删掉这一层而不是挪到最前。
- 目录缓存：把一个命令带 `contextEffect` 的目录经 `NativeCatalogCache` 写入再读回，命令只剩名字与描述，Claude 的声明读 `/review now` 得 `unknown`，`models()` 现取的目录得 `keep`。
- 原型链下标：Claude 实例对目录里不带效果的 `constructor`、`toString`、`valueOf`、`hasOwnProperty` 给出函数作效果，`__proto__` 给出对象。
- 其余：Claude 的开关加端点判成 `gateway:<host>`；Codex 的其他 Provider 也套用 `OPENAI_BASE_URL`；dsh 实例与声明对无目录的 `/x`、目录列出的 `/clear` 读法不同；家目录在工作区里时用户层被标成工作区路径，`CLAUDE_CONFIG_DIR` 在两者之外时状态里出现绝对路径；`stat` 与 `readFile` 之间有窗口。
