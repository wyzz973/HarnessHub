# 接力 P0 修复（G067）的合成验证（2026-11-03）

对象是 [ADR-055](../decisions/0055-relay-and-context-scheduling.md) 的第一个实施切片 G067，内容见[终稿](../proposals/relay/relay-architecture.md)第 7.6 节与第 17 节，契约见[切换契约](../contracts/switching.md) R3.6。

**证据等级**：代码完成，合成测试通过。没有运行任何真实 Harness，所以“真实引擎通过”这一栏为空；只在 macOS 上运行。业务库仍是 v12，快照格式不变。

## 环境

- 分支：`cc/relay-design`，代码随本记录同一提交。
- 系统与工具：macOS 27.0.1，Node 26.11.1，pnpm 10.12.3。依赖用 `pnpm install --frozen-lockfile --offline` 安装，lockfile 与主检出相同。
- 测试数据：只用临时目录与假 Harness peer，结束后删除；没有碰 4317 服务与任何 `data/` 目录。

## 改了什么

- **R0a 只对将要发送的内容做预算**
  - 每回合只计算欠交集合，真正要携带时才渲染并做预算。
  - 切换校验与恢复切换不再构建全量上下文；来源排除未派发的 Run。
  - 超限时提供“只发这条消息”（`send(…, { attach: "none" })`）：原样发送，不改 `throughRunId`。这个选择写进命令指纹与 `message.accepted.data.relay`，快照不增字段。
- **R0b 推进规则**
  - `src/contexts/session/domain/relay/advance.ts` 把规则写死为 `advance ⇔ dispatched ∧ (due=∅ ∨ carried ∧ (input=recorded ∨ input=unknown ∧ 已重发一次))`。
  - 命令识别移到 `run.authorized` 之前，由 Driver 的 `classify` 判定。
  - 精确分支增加一个条件：位置之后，同一 harness/control 上没有派发过 Run。配置承接改读该 harness/control 最后一个已派发的 Run。
  - `BackendResult.input` 与 `command` 是瞬时字段，持久化之前剥离。`run.ended` 事件数据带 `input`、`contextEffect` 与 `relayResendOf`；只携带来源历史的回合，在 `run.context_prepared` 里记 `carriedOrigin: true`。
  - 判断“是否重发”只看当前原生会话。非精确分支的绑定在第一次携带之前，一直欠着来源历史。
  - unsafe 结束时，在同一事务里把待决切换记为 `failed{SWITCH_SOURCE_UNKNOWN}`，排队的 Run 记为 `SWITCH_NOT_EFFECTIVE`。
- **R0c 插入前与插入后**：五家 Driver 各自把结果映射为 recorded、not_recorded 或 unknown，依据是[第一轮 R8](../proposals/relay/round1/r8-gap.md)的源码级事实与本机安装包源码，Runtime 不按产品名分支。`ControlError` 增加有界的 `remoteMessage` 与 `remoteFields`，供 Driver 区分插入后失败（`json-rpc-process.ts`，经 G031 修改）。主要映射：
  - Claude（claude-agent-acp 0.99.1）：模型调用失败的 errorKind 记 recorded（如 rate_limit、overloaded）；入队前拒绝记 not_recorded；认证失败（`-32000` 且不带 data）记 unknown。
  - OpenCode（2.2.5）：送达后的服务失败记 recorded；送达前的参数类拒绝、“已有活动 prompt”与 CatalogNotReady 记 not_recorded。
  - Hermes（v0.22.5）：以下两种拒收记 not_recorded，并提示先执行 `/discard`：
    - 网关不可用；
    - 有未决 unknown 准入时的拒收（“nothing was submitted”），以及精确的 `not_found`、`invalid_params`、`permission_denied`。
  - Codex：没有 turnId 的拒绝记 not_recorded，看到 userMessage 条目记 recorded。
  - OpenClaw：`model_not_applied` 记 not_recorded，回合后转录里出现 user 行记 recorded。
- **R0d 命令目录**
  - 增加 `contextEffect`、`hiddenCommands`，以及复刻原生解析的 `classify(text, catalog, attachmentKinds)`，各 Driver 的 `startText` 与它共用同一套解析。
  - Hermes 按 `_slash_command` 解析：
    - 命令表是核对于 v0.22.5 的副本（104 条命令，含别名共 130 个名字），注册表之外的词，宣告过的算命令，否则算内容；
    - 只有图片附件让 Hermes 不解析命令；
    - `/compress` 的预览参数记为 none，没有可压缩内容时记为 noop；
    - 表外又未宣告的“像命令”的输入，不按 E3 记 recorded，这样表过期时最坏只多重发一次。
  - Codex 只认精确的 `/export`、`/compact` 与 `/skill:`，不去前导空白，带附件时按普通文本。
- **R0e 数据根**：启动时沿两条父链（解析符号链接前与后）按 (dev, ino) 比较数据根与工作区，并在工作区里有界查找 `.harness-gateway.json` 标记。查找逐项读取，深度 ≤6、≤2,000 项、≤100 ms，符号链接只看不进。数据根与工作区互相包含时，启动时告警。

## 独立审查

由一个没有参与实现的代理对照规格审查，共三轮：
1. **第一轮**：3 条重要、7 条次要（F1–F10）。重要的三条是：
   - Hermes 有未决 unknown 准入时的拒收会让欠交事实丢失；
   - Hermes 的命令识别过宽；
   - Claude、OpenCode 插入后的失败没有记为 recorded，会重复注入。
2. **第二轮复核**：F1–F7、F9、F10 已消除，F8 部分消除。新发现 3 条次要问题：Hermes 带文件附件的命令被判为内容；只携带来源历史的回合没被认作已携带；一条按耗时断言的测试。
3. **最后一轮**：上述问题与两个附带问题（Claude 认证错误的用例形状、Hermes 命令表的稳妥写法）都已修正。这一轮由测试、审查脚本的复跑和主负责人的全量重跑核实，没有再做第四轮独立审查。

复核结论：新增的 recorded 映射只在回合开始之后才会产生；not_recorded 映射都发生在准入或送达之前。审查方没有找到会漏交的路径。即使误记成 not_recorded，后果也只是下一条多带一次。

## 已知局限（v13 关闭，或由后续任务承接）

- **v12 没有纪元，也没有 executedOn**。due 包含本绑定自己在位置之后的回合，例如命令回合，下一份信封会引用它们。清空之后的旧位置仍会被判为精确分支。
- **新原生会话的首个回合仍带空历史的信封**，这是 R4 D7，留给 G070。
- **“只发这条消息”只有 Runtime 接口**。HTTP 与界面归 G073；`CONTEXT_TOO_LARGE` 的提示里已写明这个选项。
- **两种情况会在程序启动之后才报 `CONTEXT_TOO_LARGE`**：输入在读目录之后才确定是内容（疑似命令，例如 Hermes 目录未读时的未知 `/词`）；以及复用保留进程的回合，这时保留进程会被关闭。
- **以下按 unknown 处理，可能多重发一次**：
  - OpenCode 的 PromptConflict，以及通用的 “Internal service failure”；
  - Claude 的认证失败；
  - Hermes 的 `admitted_turn_failed`，以及表外又未宣告的“像命令”的输入。
- **Hermes 依赖 v0.22.5 的细节**：
  - 命令表取自这一版；noop 按这一版的英文回执识别；
  - 图片超过 Hermes 的入站媒体上限而被降级为文字时，命令照常执行，Hub 却判为内容。默认上限 128 MiB，大于 Hub 的 20 MiB 附件上限；
  - 带文件附件时，Hermes 看到的命令参数里含文件指针，效果依赖参数的命令可能与 Hub 的判定不一致。
- **`carriedOrigin` 从 G067 起才记录**。此前只携带来源历史的旧回合会被当作未携带，最多多重发一次。
- **v12 没有工作区观测器（G071）**，数据根检查只用于启动告警；`chat.ts` 入口没有这条告警。
