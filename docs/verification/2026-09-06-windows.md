# 验收：Windows 原生开发与 Codex

日期：2026-09-06
范围：Windows 引擎发现与启动、Job 监督、文件产物、秘密存储、正式 API、控制台与本地启动入口。
结果：本机 `pnpm check` 退出码 0，下列原生及真实 Codex 场景已验证；其他平台与引擎不扩展为通过。

## 环境与版本

Windows 11 专业版 10.0.22621 ARM64，Node 24.20.0 win32/arm64，pnpm 10.12.3，HarnessHub 0.1.0。仓库位于桌面 HarnessHub，基线 commit 为 `162f39d88e35b45a195b479d918caaac6120d3d6`，分支 `feat/windows-native-support` 加本次未提交修改。依赖及 Node 安装在仓库本地目录，系统 Node 和全局 PATH 未更改。

本机 Codex CLI 为 0.153.4，使用桌面应用提供的 `codex.exe`；ACP Adapter 固定为 `@agentclientprotocol/codex-acp@1.10.0`，位于忽略目录 `.tools/adapters`。真实任务沿用现有登录与模型配置、初始 read-only 模式，工作目录为专门创建的中文测试目录。ACP 的 currentModelId 报告 `gpt-6-astra`；这不代表独立核实了服务端账单模型或费用。用户授权最多 3 个任务、每个最多 60 秒，本轮恰好使用 3 个，之后的浏览器和启动检查未调用模型。

原生 helper 使用 Windows 自带 .NET Framework C# 编译器构建 AnyCPU；浏览器为本机 Edge 152.0.4191.62。启动脚本另在 Windows PowerShell 5.1 验证，使用进程级 RemoteSigned，无全局执行策略变更。

早期整仓检查揭示了 Unix 可执行权限假设、Windows chmod 不能证明私有权限，以及重复启动原生文件 helper 带来的开销；实现改用 Windows executable 解析、DACL 验证及每次采集复用一个可等待关闭的文件会话。其他两处失败来自测试的就绪/等待假设：CLI deadline 测试现在等待实际父子 PID 并断言存活，再通过测试时钟触发原有 1500 ms deadline，仍走真实 HTTP、SQLite、Worker 和原生清理；文件产物的第二个 Run 现在拥有独立的原有 8 秒观测窗口，不再复用第一个 Run 的截止时间。未延长 Run 预算或测试总期限，也未将整套测试串行化。

CLI 测试的第一次时钟方案暂停了 Undici 所需的 timer，导致检查取消；已改为在该时钟作用域使用真实 node:http 请求，恢复时钟后再读取 SSE。这些失败日志保留，不能将失败轮次计作成功；最终结果对应修改冻结后的检查。

### 运行与文件

Windows 原生进程测试覆盖 Worker 执行前归属、缺 helper 拒绝、字面 Unicode argv、启动取消、probe 取消、后台后代回收和 Gateway 强制退出后重启。重启保存原 Run 为 interrupted，唯一终止事件、身份匹配清理，不自动重跑。详情见 [进程验收](2026-09-06-windows-process.md)。

文件测试覆盖中文/空格、大小写别名、超过 260 字符路径、DACL、ADS/保留名称/越界拒绝、junction/硬链接、修改中的文件、读取租约、不可变快照、hash 和 SQLite 重启。Windows 文件会话在清理后不留下 helper。秘密测试实际执行接近 8 KiB 的 Unicode DPAPI 往返、密文不包含明文、不可变引用与删除、env 大小写及私有文件校验；包括 Codex MSIX 下 LocalAppData 重定向的物理路径处理。

在启动脚本拥有的两个服务上，正式生命周期示例生成 Run `7838b092-b8b0-4119-9fed-376f11c25f1d`，completed、9 个事件、幂等核验成功；产物 SHA-256 为 `49a705c83cba88ad4504499b59a64790a6ad2b8deb3f837ada6bb56b061bf76a`。强制终止该次启动器后，现场核实两服务与两 helper 不存在，两个监听端口为零。

### 控制台

生产页面通过真实浏览器读取 Gateway。引擎页显示 Codex ready、启用和默认状态；配置框显示系统安全存储文案。浏览器仅允许 GET 请求，关闭未保存配置，无写操作、模型请求、页面错误或 API 失败。当前开发机的 Codex 登记保存在 `data/demo`，继续查看时保留 `--demo`，目录语义见 [Windows 指南](../windows.md)。

## 未验证项与限制

- Windows 10、Windows x64、其他原生架构、SMB/UNC 根目录未在本轮运行。CI 已配置 Ubuntu/Windows matrix，尚未推送或得到本次远端结果。
- 真实 OpenCode、Claude Code、Pi、DSH、OpenClaw 及特殊第三方 MCP 创建方式尚未做 Windows 模型验收；fixture 中的 Skills/MCP、权限、工作流、恢复和评测通过不能替代这些真实引擎的证据。
- Codex 当前注册仍保守地声明不支持 HarnessHub Session 恢复；ACP 的 resume 宣告不代替本轮缺少的真实恢复验证。取消任务未获得完整 usage/费用时保持未知。
- Job Object 控制所属进程树，不提供文件、网络、桌面或提权沙箱；WMI、服务、计划任务和外部 broker 不在普通进程后代证明内。DPAPI 不隔离同一用户下的恶意进程。
- Windows 标准用户不能创建文件 symlink 的测试如实跳过；未开启开发者模式或修改全局策略。完整发布 ZIP/安装包及干净机器发行验收仍属于 HH-023。
