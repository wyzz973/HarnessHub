## 看到的问题

- **被拒绝的改动，两家的状态词不一样。** 同样是用户拒绝了审批，Codex 的那条改动记为“已拒绝”，Claude Code 的记为“失败”（它在被拒后把这次工具调用报成了出错）。审批条目本身两家都记对了。要在归一里补一条：审批被拒的那个动作，状态是“已拒绝”，之后 Harness 再报出错也不改回去。
- **启动的次序。** 应用先打开对话库（这时已经备份并升级），之后的检查（锁目录的权限）失败时，启动失败而库已经升级。升级本身没问题，但对真实数据这是最不想要的状态。已安排把不依赖所有权的检查挪到打开对话库之前。

## 没有验证

- 换家只跑了一个任务的两个方向；另两个任务、不带交接单与单家对照没有在新存储上重跑。
- 等待审批时杀掉应用再打开（审批应记为取消、回合记为结果未知、已有文字还在）：只有合成测试。
- 其余四家（OpenCode、DeepSeek Harness、Hermes、OpenClaw）在新存储上的新回合：只有试用数据根里旧回合的升级。
- 页面：这一版线上形状没变，条目的先后还没上屏；2,000 回合的对话、20 MiB 的单条回复在浏览器里的表现要等分页那一路合并。
