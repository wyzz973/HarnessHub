## 6. 受阻项与根因

- **Hermes 0.12.0 的审批。** 本机安装的 `tools/approval.py` 以 `allow_permanent` 参数调用审批回调，ACP 适配层的回调不接受这个参数，异常后一律按拒绝处理，审批请求从未发给 HarnessHub。上游 v0.21.6 的回调已接受这个参数。处理：Hermes 没有请求审批就拒绝命令时，HarnessHub 对 0.12.x 显示一条说明。HarnessHub 不修改、也不替用户升级 Hermes。
- **Cursor。** 账号套餐限制使生成任务返回升级提示，大部分能力无法真实验收。在原程序中继续时，它在新工作区要求先确认信任（Workspace Trust Required）；确认会改写用户自己的配置，按用户约束没有确认，也没有使用 `--trust`。
- **Gemini CLI 0.62.0。** 模型服务以客户端版本过旧为由拒绝（`NATIVE_CLIENT_UNSUPPORTED`），没有可验收的回合。
- **dsh 的审批。** 生效的权限预设无法观察：ACP 入口不回报预设、不处理 `/permission`，本机也没有可读的设置文件。本机预设为 danger-full-access，不会请求审批。界面只说明规则，不读取 dsh 的设置。
- **Hermes 的一次 `SESSION_BLOCKED`。** 工作区放在系统临时目录（Hermes 拒绝写入的敏感路径）时，一次验收以 `SESSION_BLOCKED` 结束，根因没能复现。改用普通目录后，同一验收 29 秒通过。

## 7. 暂缓与取消的决定

- **ADR-027 直连 OpenClaw Gateway：暂缓。** 直连能拿到完整的工具流和审批，但需要在用户正在运行的 Gateway 上配对新设备，并由 Hub 处理 Gateway 凭据，会改变用户的安全状态。将来的提案必须：在界面上逐项确认并给出撤销方法；先只订阅只读事件；只针对 Hub 自己的会话；先在独立的测试 Gateway 上验证。
- **自定义入口（发现清单）的编辑界面：放到下一阶段。** 先写 ADR 再实现。
- **G(i) DSH Desktop 的命令位置：取消。** 没有官方的 DSH Desktop；官方安装方式是 `npm install -g`，安装位置已在搜索范围内。

## 8. 本阶段的新发现与处理

- **测试留下的工作区租约文件。** 工作区租约目录（每个本机用户一个，所有 Gateway 共用）里累积了约 4083 对租约文件（约 79 MB），大多是测试为临时工作区留下的。它们不影响正确性，但每轮完整测试约增加 50 对。这个目录也是运行中服务的租约命名空间，所以没有清理。
- **已处理（[ADR-041](../decisions/0041-workspace-lock-root.md)，已部署）：** 增加 `--workspace-lock-root`，测试一律使用自己的临时租约目录。完整测试前后，共享目录的文件数都是 8166。
- **下一阶段先写提案：**
  - 清理已有文件：只删除同时满足三个条件的文件对——记录的工作区已不存在、状态为未持有、能取得独占锁；作为显式维护命令，先 `--dry-run` 列出再删。
  - 租约目录的耐久性：`/tmp` 会被系统定期清理，重启也可能清空，被隔离的租约状态可能随之消失，隔离就会静默失效。评估迁到每个用户的耐久位置，并给出迁移方式。
- **迟到的审批消息。** 另一个审批代理实例早先发出的条件，直到阶段末尾才送达本会话。处置见第 11 节。
