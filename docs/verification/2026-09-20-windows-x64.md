# 验收：Windows x64 十引擎、工具包、离线交付与干净机器

日期：2026-09-20
范围：比赛决赛版在 **Windows x64** 上的引擎可用性、比赛接口规范 v1.1、一键工具包、离线开发包安装链路，以及"全新无环境电脑"的运行前提。
结果：部分完成。模拟模型下 10 个引擎全部通过；真实模型下 8/10 通过，其余两个的根因已修复并分别复测通过（合并后的整包复测未完成）。**公司自有 GLM 网关、真实 Office/Outlook 操作、桌面会话、Windows 10 与 ARM64 未验证。**

## 环境与替身

- 执行环境：GitHub Actions `windows-latest` x64 运行器，以及同一运行器上的 `mcr.microsoft.com/windows/servercore` 干净容器（`--network none`）。
- 被测产物：CI 构建并发布到 Release `competition-latest` 的 `harnesshub-competition-full-windows-x64.zip`，以及 Release `offline-dev-latest` 的离线开发包。测试使用包内 `runtime\node.exe`，不安装任何东西。
- 引擎：发行包内固定版本的 opencode、codex、qwen、hermes、pi、gemini、mimo、dsh、openclaw、kimi。
- 模型替身：DeepSeek `deepseek-flash`（推理模型，流式返回 `reasoning_content`，支持工具调用），置于开发机上只接受流式的严格代理之后，对外**呈现为 `GLM-V5_1-DX`**。代理拒绝 `stream:false`、非该模型名、`stream_options`、`parallel_tool_calls`、`reasoning_effort`、`max_completion_tokens`、`store`、`metadata`、`service_tier`、`developer` 角色、`json_schema` 输出与 strict 工具定义。真实密钥只存在于该代理进程的环境中，不进入 GitHub。
- 模拟模型：`scripts/mock-company-model.mjs`，规则同上并强制回传 `reasoning_content`，用于不需要真实模型的验收。

**这不是公司模型的验收。** 公司网关 `GLM-V5_1-DX` 的真实行为（参数容忍度、是否接受回传推理内容、超时与限流）必须在内网另行验证；为此提供了 `HARNESSHUB_MODEL_DROP_PARAMETERS`、`HARNESSHUB_MODEL_REASONING`、`HARNESSHUB_MODEL_IMAGES` 三个现场开关，见 [交接说明](../handoff.md)。

## 干净机器（无任何运行时、无网络）

容器内确认缺失：`vcruntime140*.dll` 等 VC++ 运行库不在系统目录、PATH 中没有 node/git/python、只有 Windows PowerShell 5.1。在此条件下发行包自带运行时完成了完整性校验、无模型自检与 10 引擎模拟模型验收。

- 静态 PE 导入扫描（877 个文件）只剩 3 个无法解析的导入，全部来自 Hermes 运行时中**可选的 pywin32 扩展**（`axscript.pyd`、`dsound.dll`、`mfc140u.dll`），不影响已验收的路径。
- **解压路径长度**：包内最长相对路径 196 字符，超过 180 字符的有 34 条。把包解到 `C:\Users\<用户>\Downloads\harnesshub-competition-full-windows-x64\` 这类默认位置会超过 Windows 260 字符上限并静默丢文件；容器中把已解压目录搬到含中文的长路径时即因此失败。必须用 7-Zip 或 `tar.exe` 解到短路径（例如 `D:\hh`）。

## 未验证

- 公司自有 `GLM-V5_1-DX` 网关的真实行为。
- 真实 Office / Outlook 的 COM 操作（容器与 CI 运行器均未安装 Office），办公 Skill 中的 COM 配方只经过语法与路径检查。
- 桌面（非服务）会话下的行为：CI 与容器没有桌面外壳，因此"通过资源管理器代启动、使应用在会话结束后仍然存在"这条路径未能实测。
- 办公任务集（`scripts/competition-tasks.mjs` 的 20 道题）在 Windows 上的通过率。
- Windows 10、ARM64、真实评测机与具体赛题规则。
- 合并全部修复后的整包复测（Kimi、DSH、办公工具包预装同时在一个包内）。

## 判定

按 [完成的定义](../testing.md#完成的定义)：设计已采纳、代码已完成、自动测试通过、**模拟模型下 Windows x64 十引擎通过**、**真实模型（替身）下八引擎通过且另两个的根因已定位并分别复测通过**。真实公司模型与真实桌面办公操作仍未通过，不能据此认为比赛任务可完成。
