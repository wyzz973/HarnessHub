# ADR 0034：控制台的中英文界面

Status: proposed

日期：2026-10-05
关联决定：[ADR 0024](0024-embedded-console.md)（内嵌控制台）、[控制台](../../packages/console/README.md#语言)

## 问题

控制台此前只有中文。开源版对标 Magpie，多数用户读英文；同时控制台的文字分散在约 60 个组件与库模块中，没有任何机制保证新增的文字两种语言都有。控制台是内嵌在守护进程中的静态单页，体积与依赖都随单可执行文件分发。

## 决定

- **自己的小目录，不引入 i18n 库**：[lib/i18n.ts](../../packages/console/lib/i18n.ts) 约 200 行，提供 `t(key, values)`、当前语言、`{name}` 占位符、英文的 `{n, plural, one {…} other {…}}`（`Intl.PluralRules`），以及按语言格式化日期、数字与美元金额（`Intl`）。值需要是 React 节点时用 [lib/i18n-react.tsx](../../packages/console/lib/i18n-react.tsx) 的 `tr`。
- **中文是源语言，按区域分模块**：[lib/messages](../../packages/console/lib/messages/) 每个区域一个模块，键以区域名开头，同一模块中写中文（`as const`）与英文（类型要求同样的键）；占位符名从中文推导，`t` 的参数因此有类型。区域分开让并行的改动不在同一个文件上冲突。
- **语言选择**：设置中的开关，保存在这个浏览器的 `localStorage`（读写都包在 try/catch 中，失败时只对当前页面生效）；没有选择时按 `navigator.languages` 取第一个中文或英文，其他语言用英文。切换时整个界面以新的 key 重新挂载，在挂载时计算的文字也随之改变。
- **边界**：守护进程的问题详情、风险告知、体检结论、预设名称等按守护进程发送的原样显示；控制台按错误码组织的文字在目录中。发给模型的提示词（连接测试、建议的任务）随界面语言。
- **检查**：`tools/check-console-i18n.test.mjs` 要求每个区域两种语言的键相同、占位符相同、键不跨区域、英文中没有中文、中文不用复数语法，并在组件或库模块（目录之外）出现中文字面量时失败（注释不算；登记的例外只有语言开关中的“中文”与按全角逗号分隔输入的正则）；各有拒绝样例。

## 考虑过的替代方案

- **i18next / react-intl / Lingui**：功能完整，但为两种语言、约 1850 条文字引入运行时与构建插件，内嵌单页与单可执行文件都要多带它们；它们的 ICU 解析与按需加载在这里用不上。占位符类型检查也要另外配置。
- **一个大目录文件**：最简单，但几个人同时改不同页面时总在同一个文件上冲突。
- **按浏览器语言自动切换、不提供开关**：用户无法在中文系统上看英文界面（或相反），也无法保持选择。

## 后果

- 新增界面文字必须同时写中英文，否则类型检查（缺键）或上面的测试失败。
- 英文文字比中文长，窄屏布局按英文检查过（390px）。
- 只有两种语言；增加语言需要新的目录、`locales` 与 `localeNames`，以及该语言的复数规则（`Intl.PluralRules` 已覆盖）。
- 守护进程与 CLI 的文字仍是各自的语言（多为英文），本决定不涉及。

## 验证要求

- 测试：上述目录与字面量检查，以及消息格式（复数、数字与金额格式、React 节点占位符）的用例。
- 浏览器：英文界面走完主要流程，逐页检查渲染出的文字与 `aria-label`、`placeholder`、`title` 中没有中文（守护进程的数据除外），并在 390px 与深色模式下检查；切换语言后刷新仍保持所选语言。
