# ADR-042：重写 Web 界面，沿用数据层与对话状态逻辑

状态：accepted，2026-10-12。用户确认设计稿后要求直接实现；实现取舍由用户授权的审批代理（Fable 5.1）审阅。

2026-11-01 起，视觉方向与第 4 节（字体与内容安全策略，含其补充）由 [ADR-054](0054-design-language-2.md) 取代；第 5 节的侧栏分组与审批位置由 ADR-054 修订。

## 背景

- 用户认为第一链路已可用，要求完全抛弃演示性质的前端，重新设计全部页面、细节、交互逻辑、UI、UX 与动效。
- 设计稿在 Claude Design 画布中完成并经用户确认（16 个画板，私有链接见 `docs/verification/frontend-redesign-2026-10-12.md`）。用户选定：
  - 对标 Claude Code 桌面版的交互逻辑与信息架构，视觉原创；
  - 以对话为中心，右侧详情栏可收起；
  - “精密中性”的视觉：暖灰底、单一蓝紫强调色，明暗两套；
  - React + Vite + Tailwind + shadcn（Base UI 底座）。
- 现有前端里，数据层（`api.ts`、`session-stream.ts`、`attention.ts`、`tool-tree.ts`）有单元与集成测试；`App.tsx` 中的对话状态逻辑承载了多项已验收的不变量：命令幂等键、未确认请求的保留、草稿按对话保存、选择切换自动应用、实时连接的重连与水位、安装任务的确认。

## 决定

1. **重写全部视图，保留数据层与状态逻辑。**
   - `api.ts`、`session-stream.ts`、`attention.ts`、`tool-tree.ts` 不改行为。
   - `App.tsx` 的状态逻辑保留，只改它渲染的界面，以及新界面需要的页面导航和偏好。
   - 所有组件与样式重写，旧组件与旧 `styles.css` 删除。
2. **技术栈。**
   - 沿用 React 19 + Vite 8。
   - 样式改为 Tailwind CSS v4（`@tailwindcss/vite`），设计令牌定义在 `styles.css` 的 `@theme` 与明暗两套 CSS 变量中。
   - 交互原语使用 Base UI（`@base-ui/react`）：弹出层、菜单、对话框、选项卡、开关、提示。组件按 shadcn 的方式放在仓库内（`web/src/ui/`），不引入运行时主题库。
   - Markdown 沿用 `react-markdown` + `remark-gfm` + `remend`：它已处理流式片段修复、只读链接与图片替换。代码块与差异的高亮使用 Shiki 的细粒度包与 JavaScript 正则引擎，按需加载，不用 WASM。
   - 版本一律精确锁定，选择发布满两周的版本。
3. **不采用的部分（与设计讨论时列出的选项相比）。**
   - TanStack Router：只有对话、我的 Agent、设置几个区域，地址中的片段还承载启动令牌，继续用片段记录当前对话与页面。
   - TanStack Query：页面状态主要是带幂等键的命令与实时事实流，不是可缓存的读取。
   - Streamdown：它的流式修复与链接加固与现有管线重复，还会带入 Mermaid 与 KaTeX 的大块代码。
   - `@pierre/diffs`：差异来自工具结果中的统一差异文本，自己按行渲染即可。
   - `cmdk`：命令面板与选择器共用同一套键盘与输入法处理（`isComposing`）。
4. **字体与内容安全策略。**
   - Geist 与 Geist Mono 的可变字体随前端打包（`@fontsource-variable/*`，OFL-1.1）。
   - 中文最初使用系统字体，内容安全策略不变。交付时把“改用远程中文字体”作为选项交给用户，用户选择放开（见下文“补充”）。

### 补充：中文改用 Noto Sans SC 远程字体（2026-10-12，用户决定）

- 页面从 Google Fonts 加载 Noto Sans SC（400、500、600、700），各平台字形一致；没有网络时回退到系统字体（PingFang SC、Microsoft YaHei 等），页面照常可用。
- 内容安全策略只为这一项放开两个来源：`style-src` 增加 `https://fonts.googleapis.com`，`font-src` 增加 `https://fonts.gstatic.com`。脚本、连接、图片等其余来源不变，仍只允许本机网关。
- 页面已带 `Referrer-Policy: no-referrer`，样式表链接也写明 `referrerpolicy="no-referrer"`：向 Google 的请求不带页面地址。代价是打开页面时会访问 Google 的服务器。
- 浏览器测试在本地应答这两个域名的请求，测试不依赖网络；主题测试断言完整的内容安全策略、样式表请求与字体栈。
5. **新的交互（来自设计稿）。**
   - 侧栏按状态分组：等你处理、进行中、今天、更早。顶部铃铛打开跨对话的收件箱，同时放通知开关。
   - 审批与提问卡片放在对话里，挂在当前回合的末尾，写明期限的来源。卡片获得焦点时按 1–9 选择对应选项。
   - 过程默认折叠为一行摘要（例如“读取 2 个文件，执行 1 条命令”）。标题栏可在简洁与详细之间切换，偏好保存在浏览器。
   - 右侧详情栏分为改动、过程、计划、后台、执行五个页签。改动来自本对话工具结果中的差异，只读，不提供撤销。
   - 中途切换使用 Harness、模型和思考强度的选择器。切换生效后，对话中显示“从这里起由 X 接手”的分隔线。
   - 回复进行中，可以先写下一条，由页面暂存：
     - 本轮正常结束后自动发出；本轮失败、取消、结果待核实，或对话不能接收消息时，不自动发出，放回输入框；
     - 页面重新载入后放回输入框，不自动发出；
     - 发出前可以编辑或撤回。
   - 命令面板（⌘K）、快捷键表（⌘/）、新对话（⇧⌘O）。浏览器通常保留 ⌘N，所以不用它。
   - 设置页集中放外观（主题、过程显示）、通知、发现（登录 shell 目录）、服务限额（只读）、数据与关于。
6. **不做。**
   - 对话的重命名、置顶、归档：需要在会话上保存元数据，后端尚无接口。
   - 差异行评论随下一条消息发出：后续再做。
   - “模型与账号”“技能库”“用量”：只在信息架构中保留位置。

## 验证

- 浏览器测试迁移到新界面，覆盖的行为不变：选择与切换、取消、断流重连、审批、附件、分支、扩展、本机会话、保持原生进程、等待工作区与名额、诊断、版本提示、登录 shell 目录。
- 新增的交互另有浏览器测试：按状态分组、收件箱、详情栏、过程摘要与密度切换、命令面板、暂存下一条消息、明暗主题。
- 390 与 320 像素宽度没有横向滚动。
- 4317 部署前：完整测试、设计检查、开发实例上的真实 Harness 对话。
