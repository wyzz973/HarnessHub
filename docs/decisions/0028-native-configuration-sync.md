# ADR-028：原生命令改设置后的同步

状态：accepted，2026-10-11。依据[ADR-020](0020-complete-native-harness-capabilities.md)、[ADR-022](0022-native-activity-and-content-store.md)。用户要求按各 Harness 实际能力接出模型、思考档位与模式，且不隐式切换模型。

## 背景

- Hub 在每个回合打开原生会话时应用对话所选的模型与选项。原生命令（OpenClaw `/think high`、`/model x`、`/fast on`，Claude 的 `/model` 与退出计划模式，Pi 扩展命令）会在原生会话内修改同一设置；下一回合 Hub 再按所选应用，原生改动被悄悄改回。
- 各原接口报告当前值的方式不同：ACP 代理以 `config_option_update`/`current_mode_update` 宣告（也有代理对客户端的 `set_mode` 不回显）；OpenClaw 桥对斜杠命令的改动从不推送，设置只在 Gateway 会话行（模型、思考、详情、思考输出、用量页脚、提权）与 `chat.history`（快速模式）里；Pi 以 `get_state` 报告模型与思考档位，恢复会话文件且未指定模型时自己恢复上次的模型与档位；Codex app-server 没有修改设置的原生命令，服务端改路由是单轮行为。
- 选择只能随一次生效的切换（新纪元）改变；同一纪元内，回合选择就是上次应用的选择。

## 决定

1. **记录原生回报。** Driver 可实现 `nativeConfig()`，在回合结束、关闭前报告原生会话当前的模型与选项（目录中的 ID 与值）。Runner 校验后写入该原生引用的 `observed`（业务格式 v9）；读取失败或无效时记 `native.config_unreadable`、清除旧回报，回合结果不受影响。没有派发的回合保留原回报。
2. **同一纪元沿用原生值。** 下一回合打开原生会话前，若该引用的上一回合与本回合同一纪元，所选请求的键中原生回报不同的值，按原生当前值显式应用（不依赖原程序是否在恢复时保留），并提交 `native.config_carried`。未请求的键从不应用，由原程序自己决定。
3. **显式选择重新生效。** 任何生效的切换（包括切到相同选择）开启新纪元，下一回合按所选完整应用。界面在沿用时显示“原生命令已改为 …；下一回合沿用，不改回所选”，并提供“改用所选设置”（提交与当前相同的切换）。高级配置中的原生会话显示原生当前值。
4. **各 Driver。** ACP 报告代理宣告的当前值（`set_mode` 成功后按已应用值记录）；OpenClaw 每回合后经原 CLI 读取 `sessions.list`（按本会话 key 精确匹配）与 `chat.history`，按桥的默认值映射到桥的选项 ID；恢复的 OpenClaw 会话在检查图片时按会话行的模型；Pi 读取 `get_state`，恢复会话时只有选择了模型才指定模型；Codex 不实现（没有可由命令改变的会话设置，改路由仍是逐轮警告）。
5. **数据。** v8→v9 只改版本号；v8 数据中出现回报即整笔拒绝。视图 `nativeStates[]` 增加 `observed` 与 `carried`，不含私有引用。

## 影响

- 升级到 v9 前备份数据根；回退旧程序需恢复备份。
- OpenClaw 每回合多两次原 CLI 只读调用（与转录读取并行）。
- 原生值被沿用时，回合的 `selection` 仍记录用户所选；实际应用的值见 `native.config_carried` 与原生回报。
- 若某个代理把自动路由后的模型宣告为会话当前模型，同一纪元的下一回合会沿用它；目前接入的代理未见这种宣告（Codex 改路由不经此路径），出现时需按该代理单独处理。

## 否决方案

- 把原生改动写回对话选择：等于 Hub 自行切换选择，违反不隐式切换的约束，也会制造用户没有发起的切换记录。
- 同一纪元内完全不应用所选值：依赖每个原程序在恢复时保留设置，ACP 代理不一定如此（例如恢复后回到默认模式）。
- 每回合按所选强制应用（原行为）：静默撤销用户在原生会话中的命令。
