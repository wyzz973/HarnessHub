# ADR-012：Harness 安装升级管理与原生工作台

状态：accepted（2026-10-10，用户明确要求重做UI/UX/动效，并以Magpie/CC Switch为参考集中显示品牌、安装、升级与更新）。不重新开启自动择优或发行平台矩阵。

## 决定与边界

将只读目录与实际安装管理分开。只有已审核的配方提供安装动作；未知来源、运行时不兼容或未支持方式给出明确原因。点击安装/升级是操作授权，后端实际执行有界任务，不把命令复制或打开外链称为安装成功。用户指令授权本切片下载安装，但默认写入HarnessGateway私有管理目录，不覆盖系统安装、不修改用户全局配置。

管理上下文拥有InstallationJob、不可变安装版本与默认指针；公共Session继续属于Session上下文。任务身份与命令身份分离，提交幂等，更新使用默认revision前置条件。安装写入独立stage；退出码0后还要校验来源/package、bin、版本、路径及清理。仅完整验证后原子发布新安装及默认指针。已运行的Harness使用原捕获路径；升级不覆盖旧目录，新一轮通过新的受管默认选择并记录实际安装身份。

安装优先级是显式描述override、已发布受管默认、系统PATH。未指定control的新选择优先使用唯一已发布受管入口；已明确或已准入的control保持独占，不因其他入口安装而改写。HTTP的defaultControlId只表示入口默认，与自动择优Harness无关。原只读discover不触发下载或运行；未声明管理resolver时旧发现行为不变。注册目录的控制配方与npm/native安装配方不混为一谈，尤其Codex native不能以安装codex-acp包装器冒充。

Job采用queued/resolving/installing/verifying/activating/completed及cancelled/failed/unknown。日志与结果分别持久记录，有结构/字节/时间/并发上界。进程group与其流由任务拥有；取消受理、进程清理与终态分别确认。重启后在途Job标unknown、queued取消，不自动重跑或激活未知stage；旧默认保留。runtime关闭后安装manager完成shutdown，才释放provider与store owner。

Node/npm、Python/uv、归档来源分别适配，私有运行环境与包缓存使用当前宿主。需要的依赖可作为同一安装计划的私有依赖，不能借安装修改宿主全局Node/Python。下载若来源提供SHA必须匹配；未提供时明确记录HTTPS来源与实际摘要，不伪称已核对官方摘要。归档路径、链接、体积必须验证，不能以不安全解压换取覆盖数量。

当前用户优先做核心；全平台/所有发行版、卸载/GC、自动批量升级、商业产品登录与模型适配后置。安装完成只表示管理的入口文件/版本通过，不代表登录、协议执行或任务质量通过。

## 界面

重做为现代原生工作台：224px侧栏、56px统一页头、14–15px正文与至少12px次级信息。品牌图标使用可追溯静态SVG；默认离线打包，不从CDN动态加载。深墨主按钮、清晰白面板、品牌颜色承担识别。Harness列表显示版本、来源、安装/更新动作，详情侧板显示配方、阶段与日志；聊天选择器具备搜索/分组，选择与输入保持相邻。页面/浮层/侧板使用160–240ms细微动效，尊重reduced-motion，保持键盘与触屏操作。

## 责任与验证

管理负责人独占management契约、领域/应用/基础设施/安装Adapter与对应单元/进程/存储测试；HTTP负责人独占server/Web DTO及管理HTTP测试；前端负责人独占web；主负责人独占共享composition/Binding/Session安装事件、依赖、工程门禁与最终链路验收。每个文件只有一个当前修改owner。

验证必须保留真实数据库、进程、HTTP与前端；仅以夹具替代不确定外部包仓库/安装程序。覆盖幂等、CAS、取消竞态、重启、损坏/越界归档、日志预算、验证失败不发布、显式override不fallback、旧Run与升级并发。再做一次真正私有安装/更新与正式入口使用的验收，真实云模型仍不由此推断。设计、合成测试、真实下载/安装与实际调用分层记录。

调研来源与当前版本见docs/research/harness-management.md；重要发现：Magpie安装动作目前生成命令供用户执行，升级是后台执行；我们的目标包含真正一键安装，不能直接复制前者的行为。
