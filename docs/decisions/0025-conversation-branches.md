# ADR-025：对话分支与原生会话副本

状态：accepted，2026-10-11。依据[ADR-020](0020-complete-native-harness-capabilities.md)、[ADR-024](0024-native-session-operations.md)。用户要求接出原生会话的恢复、分支与压缩。

## 背景

- 原接口各有复制会话的方式：Codex `thread/fork`、ACP `session/fork`（OpenCode、Claude 声明）、Pi 恢复会话文件后 `clone`。OpenClaw 桥对 `session/fork` 返回 Method not found，Gemini、Cursor 没有实现。
- 已有的“重新建立原生会话”（ADR-020）只是在同一对话里放弃旧原生引用，不是分支。
- 公共 Session 的 Run、消息与命令互相引用，不能把另一个对话的 Run 复制过来而不破坏这些约束。
- Hub 只记录原生会话最后同步到哪个 Run（`throughRunId`），不知道每个 Run 对应的原生回合身份。

## 决定

1. **分支是新对话。** 在已完成的回复后分支，创建新的公共 Session：同一工作区与选择，`origin` 记录源对话、分支点和到该点为止的公共消息（含附件引用，源本身是分支时连同其来源一起展开）。引用历史不可变、不重新执行，有 1 MiB 上限；新对话从自己的第一条输入开始积累 Run。业务格式升级为 v8（v7→v8 只改版本号），旧程序不能读取 v8。
2. **原生副本只在精确位置建立。** 只有源对话当前选择的原生会话恰好同步到分支点（`throughRunId` 等于该 Run）时才做原生 fork；从更早的回复分支、源会话使用受管 Provider、或没有就绪原生会话时，新对话以公共历史继续，第一条输入带上引用历史（`branchedHistory`）。
3. **fork 在 Runner 中执行。** 新对话以 `fork-pending` 引用（源 checkpoint）创建，Runner 在它的任何输入之前用独立连接执行 fork：先提交 `forking` 再发请求；成功并确认清理后变为 `ready` 并保存副本自己的引用；原接口明确拒绝（未声明、Method not found、扩展取消）时归档引用、以公共历史继续；连接中断等无法确认的结果保持 `forking`，与 `unconfirmed` 一样阻止原生使用，需用户显式重新建立原生会话。fork 连接不打开其他会话，副本的回放与通知只计数、不归属。
4. **源对话不变。** 分支不向源对话写入任何事实，源原生会话不被继续。
5. **接口与界面。** `POST /api/v1/sessions/:id/fork {commandId, throughRunId?}` 返回新对话（命令幂等）；会话视图包含 `origin`，原生状态增加 `forking`。回复的操作中提供“从这里分支”；分支对话顶部显示来源、条数、原生副本状态与可展开的引用历史，可回到原对话；侧栏以“分支 · 首条消息”命名尚无输入的分支。

## 影响

- 升级到 v8 前备份数据根；回退旧程序需恢复备份。
- 原生副本由原程序创建并保留在它自己的会话存储中，Hub 不删除。
- 未做：在任意历史回合处做原生 fork（需要记录每个 Run 的原生回合身份）、原生会话列表与导入。

## 否决方案

- 把源对话的 Run 复制进新对话：会破坏命令与 Run 的对应关系，也会让“已完成”的执行证据出现在没有执行它的对话里。
- 在任意位置做原生 fork：Hub 不知道原生回合身份，副本会包含分支点之后的内容。
- 拒绝时直接失败：分支仍可从公共历史继续，失败只会让用户失去分支。
