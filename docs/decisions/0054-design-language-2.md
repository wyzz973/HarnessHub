# ADR-054：设计语言 2.0：中性外观、系统字体、校准的动效与新图标

状态：accepted，2026-11-01；2026-11-02 补充集成时的取舍（见第 5 节后的“补充”）。用户确认设计稿（Claude Design 画布第 20 版，私有链接记在[验证记录](../verification/design-language-2-2026-11-01.md)）后要求实现：“把前端实现了。注意每一个细节的处理都要处理好。”

- 取代 [ADR-042](0042-frontend-redesign.md) 的视觉方向和第 4 节（字体与内容安全策略，含其补充）。
- 修订 ADR-042 第 5 节的两项：侧栏分组、审批位置。
- ADR-042 其余约束不变：数据层与对话状态逻辑、Base UI、`react-markdown`、Shiki，以及“不做”一节。

## 背景

- ADR-042（2026-10-12）重写了 Web 界面：
  - 暖灰底、蓝紫强调；
  - 正文用打包的 Geist；
  - 中文从 Google Fonts 加载 Noto Sans SC，为此放开了内容安全策略的两个来源。
- 2026-11-01 用户对设计连续给了反馈：
  - 先说“不好看”，要清新自然；
  - 又要求“不要绿色，要简洁一些的，参考 dsh 和 Codex”；
  - 随后要求进行中状态与流式文字模仿 Claude 和 Codex，其余动效也要精益求精；
  - 最后重画应用图标，从八个方向中选定“一点分发”。
- 设计稿第 20 版共 11 块画板：设计方向、设计基础、首页、侧栏、对话（浅色与深色）、Agent、能力、动效（38 条细节）、图标、交互。
- 动效数值的来源：
  - Claude：本机 Claude 桌面版的前端包；
  - Codex：openai/codex 的源码与桌面版前端包。

## 决定

### 1. 外观令牌

令牌定义在 `web/src/styles.css`，明暗各一套。

- 浅色：
  - 底色：主区 `#FFFFFF`，侧栏 `#F9FAFB`，填充 `#F4F5F7`，悬停 `#EBEDF0`。
  - 文字：正文 `#0F1115`，次要 `#4B5059`，辅助 `#646973`。
  - 分隔：0.5 像素发丝线。
- 深色：
  - 底色：侧栏 `#111214`，主区 `#18191C`，卡片 `#1F2023`，填充 `#26272B`，悬停 `#2F3034`。
  - 文字：正文 `#F3F4F6`，次要 `#B4B8BF`，辅助 `#959AA2`。
- 颜色只表达状态：
  - 蓝色 `#3A6AE0`（文字 `#2F5FD0`，深色 `#8AB0FF`）用于发送、主按钮、选中、焦点和“进行中”；
  - 琥珀 `#F59E0B`（文字 `#B45309`）只表示“等你处理”；
  - 红 `#EF4444`（文字 `#DC2626`）只表示失败；
  - 绿色只出现在差异的新增行。
  - 其余颜色留给各家 Agent 的真实图标。
- 对比度：
  - 辅助文字在白底和侧栏上不低于 4.7:1，白字在蓝色上 4.9:1；
  - 深色一套同样达标。
- 圆角：快捷键与标签 6，行与图标按钮 8，按钮与输入 10，代码块与小卡 12，卡片与计划条 14，输入框与审批 28，胶囊与状态 999。里层圆角等于外层圆角减内边距。
- 层次：
  - 靠发丝线区分；
  - 只有输入框与弹出层带很淡的投影，输入框采用 DeepSeek Harness 的三层投影。
- 外观跟随系统；设置页里的手动选择保留。
- 不开放自定义配色。设计稿中“黑色强调色”只用于比较，不进产品。

### 2. 字体与内容安全策略

- 正文字体用系统字体：

  ```css
  "HH Quote", -apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif
  ```

- `HH Quote` 是一个只覆盖 ‘ ’ “ ” 四个字符的 `@font-face`，取本机苹方（`local()`），让中文引号显示为全角字形。
- 代码继续用打包的 Geist Mono。正文不再使用 Geist，`@fontsource-variable/geist` 依赖移除。
- 不再加载 Google Fonts，撤销 ADR-042 补充里的两处放开：
  - `style-src` 删除 `https://fonts.googleapis.com`；
  - `font-src` 删除 `https://fonts.gstatic.com`。
  - 内容安全策略恢复为只允许本机网关，页面不访问任何外部资源。
- 字号阶梯（字号/行高 · 字重）：
  - 问候 32/42 · 500；
  - 页面标题 28/36 · 600；
  - 分组标题 20/28 · 600；
  - 面板标题 17/24 · 600；
  - 阅读正文 15/26 · 400；
  - 界面 14/20；
  - 次要 13/20；
  - 说明 12/18；
  - 代码 12.5/20。
- 字重只用 400、500、600，数字用等宽数字。

### 3. 动效

按设计稿“动效”画板的 38 条细节实现，关键数值如下。

- **曲线：**
  - 出现 `cubic-bezier(.165,.84,.44,1)`；
  - 吸附 `cubic-bezier(.32,.72,0,1)`；
  - 展开 `cubic-bezier(.19,1,.22,1)`；
  - 回弹 `cubic-bezier(.34,1.3,.64,1)`。
- **时长：** 60、120、200、300、450 毫秒五档。
- **进行中状态：**
  - 一段 90° 的细圈每 0.8 秒转一圈。
  - 状态文字上的流光先等 0.6 秒，再用 1 秒扫过，每 4 秒一次；换字后重新开始。
  - 换字 180ms：旧字上移 3px 淡出，新字从下方 3px 淡入，宽度同步滑动。
  - 计时每秒更新，用等宽数字。
- **步骤：**
  - 工具步骤 430ms 进场：先从下方 5px 归位，再从模糊变清晰。
  - 完成后时态改变（“正在读取”改为“读取”），勾号用 240ms 画出。
- **流式文字：**
  - 先缓冲，每 50ms 按积压量放出，速率取权重 0.1 的移动平均，约 1 秒追上。
  - 每一小段用 700ms 淡入，曲线 `(.37,.55,.86,.88)`。
  - 一次到达超过 120 字，或每毫秒超过 1.6 字时，直接显示。
  - 末尾 7px 圆点每 1.25 秒放大到 1.25 倍；写完后 200ms 淡出。
- **完成：**
  - 细圈和状态文字先淡出，0.21 秒后“已完成”淡入，两层不重叠。
  - 1.1 秒后过程收成一行摘要。
- **展开与面板：**
  - 展开过程与计划条：高度 0fr→1fr，200ms，展开曲线。
  - 详情面板：宽度用 300ms 推开正文；内容晚 60ms，从右侧 24px 滑入。
- **审批停靠：** 输入框变形为审批框，300ms，收起 200ms。
- **其余：** 标签下划线与分段滑块滑到新位置；弹出层从 0.98 放大，120ms，收起 100ms；提示条从底部滑入，离开时缩到 0.85。
- **系统开启“减少动态效果”时：**
  - 去掉位移、缩放、模糊、弹簧与循环，只保留不超过 150ms 的淡入淡出；
  - 流光变成静止文字；
  - 回复不做淡入。
- 键盘触发的操作不加动画。
- 流式文字的缓冲放出只改变显示节奏，不改 [ADR-047](0047-stream-output-coalescing.md) 的提交与合并。

### 4. 图标

- **应用图标：** 改为“一点分发”：蓝底，一个点分出三条线。
- **网页图标：** 用 32 网格的平面版，16 像素时三条线仍然分得开。
- **界面图标：** 统一用 Lucide，描边 1.75，常用 16 和 18 像素。
- **Agent：** 用各家官方标志，或 Mac 应用图标。

### 5. 布局与交互（相对 ADR-042 的变化）

- **侧栏：**
  - 顶部依次是新对话、搜索与命令（⌘K）、等你处理（带数量）、Agent（带可更新数）、能力。
  - 其下按项目（对话的工作区）归组对话。对话前用状态点区分：进行中用蓝色呼吸点，等你处理用琥珀色，失败用红色。
  - 同一项目里，等你处理的对话排在最前。
  - 底部是设置与本机服务状态。
  - 取代 ADR-042 的按状态分组和顶部铃铛：收件箱保留，入口改为“等你处理”。
  - 收件箱跨对话列出审批与提问，写明期限属于谁；一次性选项可以在收件箱里直接决定，持续生效的选项仍回到对话里决定。这修订了 [ADR-035](0035-attention-and-request-deadlines.md) 第 6 项与“不做”第 1 项。
- **首页：**
  - 问候语、就绪摘要与工作区。
  - 输入框圆角 28。左下是附件与权限；右下是合并的选择器（图标 · Agent · 模型 · 思考档位）和发送键。
- **对话：**
  - 每轮回复前标出 Agent 的图标、名字、模型与思考强度。
  - 换 Agent 时插入“从这里起由 X 接手”，样式改为细线中间加胶囊。
  - 过程分三层：一行摘要、步骤、原始输出；连续读取合并成一组。
- **审批位置：**
  - 停在输入框的位置（同 DeepSeek Harness）。⏎ 允许一次，esc 拒绝。
  - “这个对话都允许”这类持续生效的选项不绑快捷键，只能点。
  - 数字键仍选择一次性选项。
  - 提问与计划仍挂在当前回合。
  - 审批停靠时，回合的过程行照常写正在进行的那一步，下面单独一行琥珀色“等你批准，请求停在下方输入框的位置”，点它把焦点移到审批框（补充 F）。
  - 取代 ADR-042 第 5 节“审批卡片放在对话里”。
- **输入框上下：**
  - 计划条停在输入框上方，可以展开。
  - 状态栏在输入框下方，显示轮次、步数、用时与网关已有的用量。
- **详情面板：** 页签为改动、计划、过程、后台、执行。“改动”可以在本轮与整个对话之间切换。默认关闭：没有改动时不打开，有改动时在按钮上显示数字；手动开关按浏览器记住（补充 E）。
- **新增快捷键：**
  - ⌘J：打开 Agent 选择器；
  - ⌘.：停止当前回复；
  - ⌘\：打开或收起详情面板；
  - ⌥⌘↓：跳到下一件“等你处理”；
  - ↑：输入框为空时编辑上一条。
  - ⌘/ 的快捷键表列出全部快捷键。
- **Agent 页：**
  - 卡片列表，每张卡片包括版本 · 安装渠道、状态胶囊、一句说明、升级与详情。模型与能力的数量要等网关提供汇总（补充 I）。
  - 详情在宽屏是卡片旁 360 像素的非模态侧栏，窄屏是盖在页面上的抽屉（补充 C）；下方是“还可以安装”。页面没有“返回对话”箭头（补充 D）。
  - 安装、升级、卸载的确认流程不变（ADR-043、ADR-044）。
- **能力页：**
  - 类别页签带数量，内容是条目 × Harness 的矩阵。
  - 点空格即选中，底部升起浮动条：“已选 N 处 · 会改 N 个文件 · 预览写入”。
  - 写入仍走 [ADR-045](0045-unified-capability-management.md) 的预览与确认。
  - 照画板没有页头栏，标题“能力”在左侧类别列里（补充 D）。

### 补充：集成时的取舍（2026-11-02）

五个分组合并后出现的取舍，由用户授权的审批代理（Fable 5.1）逐条裁定，主代理执行。

- **A. 完成通知不写对话标题。** 沿用 ADR-035：通知不含对话内容，标题由第一条消息生成，也算内容。交互画板的示例通知带了标题，这是有意的偏差，在验证记录 X04 写明，用户终验时可以推翻。
- **B. DeepSeek Harness 与 WorkBuddy 用各自的 Mac 应用图标。** 图标取自本机应用包，只用于辨认产品，来源与 SHA-256 登记在 `web/THIRD_PARTY_ASSETS.md`。条件：本仓库任何发布或分发之前，必须重新审查或替换这两张图标；深色模式下彩色应用图标只换底色，不反白。
- **C. Agent 详情的位置照画板。** 卡片区足够宽时，详情是卡片旁 360 像素的非模态侧栏：没有遮罩，卡片从 3 列让到 2 列，点另一张卡片就地切换，Esc 关闭并还回焦点。窄时是模态抽屉。切换按卡片区的实际宽度判断，不按视口宽度，两列卡片不能被挤到截断。
- **D. 能力页和 Agent 页没有“返回对话”箭头。** 两块画板都没有页头的返回箭头，侧栏就是返回的路。能力页没有页头栏，标题在类别列里。侧栏收起时，页面上有展开侧栏的按钮；窄屏保留菜单按钮；都可用键盘操作。设置与模型连接页没有画板，保留带返回的页头。
- **E. 详情面板默认关闭。** 依据是设计基础画板的文案：“没有改动时不打开面板；有改动时在面板按钮上显示数字。”禁止的是自动弹出；用户自己打开或关闭后，按浏览器记住。
- **F. 审批停靠时回合怎么写，照对话画板。**
  - 过程行照常写正在进行的那一步，例如“正在运行 git diff --stat · 已用 42 秒”。
  - 下面只有一行琥珀色提示“等你批准，请求停在下方输入框的位置”。它是可聚焦的控件，点击或回车把焦点移到审批框。
  - 没有进行中的步骤时，过程行才写“等你批准”。提问同理，写“等你回答”。
- **G. 两种等待状态全站只说“等你批准”“等你回答”**，侧栏、收件箱、页头、回合与系统通知一致。通知标题改为“<Harness> 等你处理”。为此改 `attention.ts` 里的三个字面量，这是“不做”第 1 项登记的例外。显示的期限来源和剩余时间不变。
- **H. 用户停止的回合写“已停止”。**
  - Runtime 取消的回合保留合约 `cancelledLabel` 的原文；`src/contracts/session.ts` 不改。
  - 页头胶囊遇到执行预算用尽、等待期限到期、服务重启这三种取消时写“已取消”，不写“已停止”：ADR-036 规定不把 Runtime 的停止说成用户的。
  - 页头、回合结束行与详情面板的“执行”页签共用同一个取词函数。
- **I. 画板上有、网关没有的内容不显示，也不估算。** 以下内容列为网关的后续工作：
  - 侧栏对话的相对时间：`SessionSummary` 没有时间戳。
  - 页面没见过的失败对话的红点：没有上次回合的结果。
  - 每一步的用时：只有回合级的 `RunTiming`。
  - “47 项通过”这类解析结果：那是对输出的解释，不是事实。
  - 其他对话做完时的通知：没有对应的事件。
  - Agent 卡片上的模型数与能力数：不是没有事实，是没有汇总接口。模型要逐家读取原生目录，能力要按类别读取。后续工作是“网关提供每个 Harness 的计数汇总”。
  - 侧栏的“新建项目”按钮：还没有对应的功能。

### 6. 只显示网关已有的事实

设计稿里的示例数据，只有网关提供了相应事实时才显示。这些示例包括费用、上下文占比、首字时间、git 分支、可更新数量等。网关没有提供的，界面不显示，也不估算、不编造。

## 不做

- 不改数据层（`api.ts`、`session-stream.ts`、`attention.ts`、`tool-tree.ts`），也不改 `App.tsx` 中对话状态的不变量。唯一的例外是补充 G：`attention.ts` 里等待状态的两个说法与通知标题，只改字面量，不改逻辑。
- 不做自定义配色、黑色强调色、第二档界面密度。
- 差异行批注继续推迟。对话的重命名、置顶、归档也不做，原因同 ADR-042：会话没有元数据接口。
