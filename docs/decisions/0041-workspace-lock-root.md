# ADR-041：显式指定工作区租约目录，测试不再写入共享目录

状态：accepted，2026-10-12。依据用户授权的审批代理（Fable 5.1）对阶段报告第 8 节的裁决。

## 背景

- 工作区租约记录哪个 Gateway 正在写哪个工作区，保证同一工作区同一时间只有一个写入者（`WORKSPACE_BUSY`、`WORKSPACE_QUARANTINED`）。
- 租约目录固定为 `/tmp/harnessgateway-workspaces-<uid>`。每个本机用户一份，本机所有 Gateway 共用，因此不同 Gateway 之间也互斥。每个工作区对应一对文件（`<路径摘要>.lock.sqlite` 与 `.state.sqlite`），不会删除。
- 测试为每个临时工作区组合应用或启动 Gateway，也写入这个共享目录。2026-10-12 时已累积约 4030 对文件（约 79 MB），一次完整测试再增加约 50 对。这个目录同时是运行中服务的租约命名空间，不能随意清理。

## 决定

1. **配置。** 在配置解析处增加工作区租约目录：
   - `web`、`chat`、`sessions` 命令支持 `--workspace-lock-root <绝对目录>`；
   - `application()` 支持 `workspaceLockRoot`，Web 服务自己组合应用时同样支持；
   - 由 `resolveWorkspaceLockRoot` 集中解析，默认值不变。
2. **校验。**
   - 显式目录必须是规范化的绝对路径，否则在创建任何内容之前以 `INVALID_INPUT` 拒绝。
   - 目录不存在时以 0700 创建。
   - 默认目录与显式目录都必须是真实目录、属于当前用户、对他人关闭，否则以 `INVALID_STORAGE` 拒绝。
3. **代价写明。** 帮助文本写明：另用一个租约目录的 Gateway，不再与本机其他 Gateway 互斥同一工作区，只用于隔离的测试或刻意独立的实例。4317 服务与开发实例都保持默认，二者必须继续共用同一个命名空间。
4. **测试。** 所有组合应用、启动 Gateway 或运行 `chat`、`sessions`、`web` 命令的测试，都使用测试自己的临时租约目录，随测试的临时目录一起删除。同一测试里重启服务时沿用同一个目录，隔离状态才能延续。真实测试同样如此。

## 不做（下一阶段先写 ADR 提案）

- **不清理已有文件。** 删除可能被其他 Gateway 持有的锁文件有竞态。提案至少包括：
  - 只删除同时满足三个条件的文件对：记录的工作区目录已不存在、状态为未持有、能取得独占锁；
  - 作为显式的维护命令，先 `--dry-run` 列出再删除；
  - 不在启动时自动执行。
- **租约目录的耐久性。** `/tmp` 不耐久：macOS 的定期维护会清理三天未访问的文件，重启也可能清空。被隔离（quarantined）的租约状态可能随之消失，隔离就会静默失效。同一份提案应评估迁到每个用户的耐久位置（例如 `~/Library/Application Support/HarnessGateway/workspaces` 或 XDG state 目录），保持“每个用户一份、所有 Gateway 共用”的语义，并给出迁移方式。

## 验证

- 集成测试（G059-NC1）覆盖以下各点：
  - 默认目录不变；
  - 相对路径和含 `..` 的路径在创建任何内容之前被拒绝；
  - 新目录以 0700 创建；对他人开放的目录和符号链接被拒绝；
  - 使用同一目录的两个应用互斥同一工作区，使用另一目录的不互斥；
  - `chat` 拒绝相对目录且不启动 Harness，`sessions` 使用给定的目录。
- `web` 命令使用给定目录，在登录 shell 的正式入口测试（G012-NC2）中核对。
- 变异检查：去掉 Web 服务对这个选项的传递后，入口测试失败。
- 完整测试前后，共享目录的文件数不变。
