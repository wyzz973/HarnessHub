# ADR-038：未经验证的版本提示

状态：accepted，2026-10-12。依据用户授权的审批代理（Fable 5.1）为排序第 5 项 F 定下的条件：只提示、不阻止使用，使用已验证版本范围，与 Codex 0.162.1 起才有的计划模式门槛分开。对应[第一链路调研](../research/first-chain-products-2026-10-11.md)的差距 5。

## 背景

- 能力矩阵记录了每个 Harness 做真实验证时的安装版本，但界面不显示。用户的版本与验证时不同，部分能力可能不同。例如上游 Hermes 0.21.6 与 0.12.0 在审批、模式和认证上差异很大，同一版本的不同构建也可能行为不同。
- 参考产品：AionUi 与已验证版本比较，不一致时仍可使用，但给出提示；Multica 按最低版本表把过旧版本下线。HarnessHub 不替用户切换或升级程序，所以只提示。

## 决定

1. **已验证版本。** `src/infrastructure/management/verified-versions.ts` 为每个 Harness 记录一个版本范围，两端都必须有真实验证记录。经适配器接入的 Harness（Claude Code 经 claude-agent-acp）同时记录适配器的版本范围。目前每个 Harness 只有一个版本，就是能力矩阵 `installation` 中的版本。单元测试核对这张表与矩阵一致：矩阵中每个 Harness 都在表中，表中的版本也都出现在矩阵的安装说明里，避免两处悄悄不一致（2026-10-21 起扩展为四处对账，见文末“区间语义”）。
2. **判断。** 产品版本和不同于它的适配器版本都在范围内时，判定为已验证。范围两端和当前版本都是 semver 时按 semver 比较，否则只按完全相同判断，例如 Cursor 的“日期-提交”版本。产品版本未知、或这个 Harness 从未验证过时，不下结论，不给提示。
3. **显示。** 管理视图增加 `verification: {state, program, adapter?}`。版本未经验证时：
   - Harness 选择器在版本后写“未经验证的版本”。
   - Harnesses 列表在版本旁显示“未经验证”，悬停说明“HarnessHub 用真实程序验证过 X（接入口 Y）。这个版本仍可使用，部分能力可能不同。”
   - 详情页写出同样的说明。

   已验证时不显示任何标记。
4. **不阻止。** 提示不影响选择、发送、安装或升级。版本相关的特化逻辑仍按各自的版本门控，例如 Hermes 0.12.x 的 60 秒审批期限、Codex 0.162.1 起的计划模式，与这个提示无关。
5. **维护。** 每次在新版本上完成真实验收，都要在同一提交里扩展这张表，并更新能力矩阵的安装说明；验证记录写明在哪个版本上验证过什么。否则，像 Codex 这样每周发布的程序，很快会对所有人显示“未经验证”。
6. **位置。** 表与判断放在管理基础设施层（`src/infrastructure/management`），不放在目录领域层：比较版本需要 semver，而领域层不引入第三方包；版本本身也由这一层探测并放入管理视图。

## 不做

- 不读取上游的最新版本来判断是否“过时”。这属于升级检查，已有“检查更新”。
- 不按版本禁用 Harness 或其能力。

## 2026-10-17 补充（ADR-044）

Pi 0.85.1 与 DeepSeek Harness 0.2.1-alpha.1 的已验证版本来自非官网安装（开发目录、源码构建）。按 [ADR-044](0044-macos-official-channels.md)，它们不再作为验收对象；表中的这两项保留为历史证据，用官方渠道重新验收后再更新。

## 区间语义（2026-10-21）

总指挥（Fable 5.1）为第一批任务 B2（版本真相）定下的修正。**本次没有改任何已验证数字。**

- **两种区间，回答两个问题。**
  - 本表（`VERIFIED_VERSIONS`）是**真实验证区间**：两端都要有真实验证记录，决定“未经验证的版本”提示和 ADR-039 的恢复命令。按 semver 比较，不是 semver 的版本只按完全相同判断。
  - 能力读表（`src/adapters/capability-reads.ts`）的 `verified` 是**读取规则核实区间**：读取规则在这个区间的版本上按官方文档、源码或包内文件核实过，决定能力页是否在版本旁标“未核实”。它可以含预发布版，比较时带 `includePrerelease`，并先去掉开头的 `v` 和数字的前导零（Cursor 的日期版本）。
  - 所以同一个版本可以在 Harness 列表里提示“未经验证的版本”，在能力页却不标“未核实”：前者说没有用真实回合验证过，后者说读取规则核实过。
- **预发布语义**（semver 7.8.5，带 `includePrerelease`）：
  - 预发布版排在同号正式版之前：`>=0.2.0 <0.3.0` 不含 `0.2.0-rc.2`。区间要从某个预发布版算起，下界就写它，例如 `>=0.2.0-rc.2`。
  - 更高修订号的预发布版在区间内：`0.2.1-alpha.1` 在 `>=0.2.0-rc.2 <0.3.0` 之内，`0.2.0-rc.1` 不在。
  - 上界 `<0.3.0` 也包含 `0.3.0` 的预发布版（如 `0.3.0-alpha.1`）；要排除它们，上界写 `<0.3.0-0`。
- **对账。** `verified-versions.ts` 的纯函数 `versionConsistency` 由单元测试（`tests/unit/verified-versions.test.ts`）用仓库里的真实数据调用，结果必须为空：
  1. 本表、能力矩阵（`plan/native-capabilities.json`）和读表列出同一组 Harness，各一次；
  2. 矩阵的安装说明写出已验证区间的上界，有适配器时也写出适配器的上界。按完整版本号匹配：`2.1.2960`、`2.1.296.1` 都不算写出了 `2.1.296`；
  3. 读表区间是合法的 semver 范围，并按上面的预发布语义覆盖已验证程序区间的两端；
  4. Harness 自己的目录包（`src/adapters/catalog.ts` 里各产品原生入口的包，不含 ACP 注册表快照里的适配器包）写的版本等于已验证区间的上界。

  每条规则都有拒绝样例，其中包括本次修正前的 DeepSeek Harness 读表区间。
- **非官网记录。** 已验证版本来自非官网安装的，在表中标 `unofficial`，目前是上面 2026-10-17 补充里的 Pi 与 DeepSeek Harness。官网渠道装不出这样的版本，所以目录包按官网渠道写版本，第 4 条对它改为要求这个版本落在读表区间内，也就是读取规则在它上面核实过。用官网渠道真实重验收后，去掉标记，并按 §5 在同一提交里更新本表、矩阵和目录包。
- **DeepSeek Harness 的修正。**
  - 读表区间由 `>=0.2.0 <0.3.0` 改为 `>=0.2.0-rc.2 <0.3.0`。npm 官网 latest 是 `0.2.0-rc.2`，ADR-045 第 3c、4 步在它上面按包内文件核实了读取规则，原区间却不含它，能力页因此在本机 DeepSeek Harness 的版本旁标“未核实”。历史上的 `0.2.1-alpha.1` 仍在新区间内。读表的依据改引 0.2.0-rc.2 包内的 dsh-skill-filesystem README 与 dsh-app-boot，5badb15 的引用保留为历史。
  - 目录包版本由 `0.2.1-alpha.1` 改为 `0.2.0-rc.2`（2026-10-18 经 4317 安装，见[管理操作验收](../verification/management-actions-2026-10-18.md)）。它只作为“目录参考”显示，官网安装仍按 npm latest。
  - 已验证版本仍是 `0.2.1-alpha.1`，所以 Harness 列表照旧对 `0.2.0-rc.2` 提示“未经验证的版本”，直到用官网渠道真实重验收。
  - 已知差距（未改）：0.2.0-rc.2 还把技能目录顶层的 `<名>.md` 和 `customSkillDirs` 里的目录当作技能来源，profile 的清单另有 `bundles`，启动时会停用补丁行写了 `disabled` 或与本版本不兼容的插件；读表还没有读这些。
- **Hermes 的版本。** 脚本渠道原来只认 `versions/<版本>` 的布局，Hermes（`~/.hermes/hermes-agent`，程序在 `venv/bin/hermes`）的版本因此总是未知，能力页一直标“未核实”。现在读它自己的虚拟环境里 `hermes-agent` 分发的 dist-info（`venv/lib/python3.x/site-packages/hermes_agent-<版本>.dist-info/METADATA`），不运行程序。读不到时版本仍为未知，安装照样算官网安装。分发名暂时按渠道目录登记在 `src/infrastructure/discovery/installation-channels.ts`，以后迁入产品描述。只在测试夹具上验证过，本机真实读取待在正式入口核对。
