# ADR-020：全部接入的Harness按原生能力接出

状态：accepted，2026-10-11。用户要求适用于所有接入和后续接入的Harness，统一聊天界面承接各自全部原生能力；沿用本机原安装、配置和登录，不修改全局模型配置。仅文本回复或协议连通不能作为完整接入标准。

## 当前共性修复

每轮新会话+公共文本不能保留原生会话状态。本轮以协议能力协商建立可恢复的原生绑定：ACP仅在实际load/resume能力开放时调用原接口；Codex使用持久thread及resume；Pi正式会话使用原CLI持久session并由原路径恢复；OpenClaw保留Hub自己的Gateway键及ACP身份并要求已有键。目录探测保持无任务、无生产状态覆盖。

公共Session保持唯一身份；每个Harness/control有私有原生绑定和已同步Run水位，切换到另一个Harness只同步后续公共事实，不重复注入已被原生会话接收的历史。公共文字接续与原生状态恢复分别记录。不得静默新建原生会话冒充resume。恢复失败保留绑定/公共历史并允许选择其他Harness；未知执行不重跑。

派发前将原生绑定标记为待确认并持久提交，后端结算和资源关闭确认后才标记可继续。进程崩溃/协议失去归属保留待确认状态。用户显式重新建立原生会话时保留旧绑定及公共历史；此动作是public_context_rehydrate而非厂商native_fork，不能自动丢弃未知原生状态。业务库v5→v6为只进事务迁移，旧历史保留，回退恢复原备份。

所有原生能力必须按原安装和接口逐项审核：模型/档位/模式、命令、skills/MCP/插件、文件/图片/音频、思考/计划/工具/用量、审批/问答、原生会话/压缩/分支/恢复、并发/后台执行和导出。只显示原生工具实际提供的选项；没有开放的接口不能伪造支持、跳过或记完整。基础能力契约在Gateway中按Driver能力派发，不按产品名称分支。原SDK类型留在Driver内。

完整接入是逐Harness验收门槛；本轮交付和未完成能力分别记录，不能将通用协议覆盖称为43个产品全部通过。已安装的七个入口是本机验收对象，未安装产品不自动安装。原生接口的限制需继续在其Adapter中研究解决，不能降级到纯聊天后宣称等价。

## 来源与验收

[ACP v1 Session Setup](https://agentclientprotocol.com/protocol/v1/session-setup)明确按能力load/resume，load可能回放历史；回放属于原生恢复数据，不能创造新的公共回复。[Pi原RPC](https://pi.dev/docs/latest/rpc-commands)与本机0.85.1源码、原Codex0.162.1生成JSON Schema、原OpenClaw2026.3.23-2源码是具体调用依据；不使用当前远端v2规则改写旧客户端。

需要真实SQLite迁移/回滚、跨进程/切换回来/服务重启、恢复回放不重复、增量上下文、恢复失败不fallback、未知/取消、原生模型配置保护和真实本机回复证据；仍未通过的能力保持未完成。
