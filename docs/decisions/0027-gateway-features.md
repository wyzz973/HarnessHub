# ADR 0027：网关的脱敏、视觉兜底、搜索模拟与图像端点

Status: proposed

日期：2026-10-04
关联：[网关功能](../gateway-features.md)、[ADR 0025](0025-magpie-routing-parity.md)（失败类别与转移）

## 问题

对标 Magpie 的网关，共享网关缺少四种能力：出站时替换提示词中的秘密、为不能看图的模型描述图片、为别家的上游模拟服务端联网搜索、图像生成端点。需要确定每种能力的范围、它们的设置放在哪里，以及网关为自己发出的调用如何记录。

## 决定

- **设置**：网关拥有的 `<dataDir>/gateway-features.json`（脱敏、视觉模型、搜索后端），与 `gateway-sharing.json` 同样由守护进程原子写入，经 `/api/v1/gateway/features/*` 与 `hh gateway …` 修改，网关通过注入的 `features()` 对每个请求读取。搜索密钥在秘密存储中，文件只记引用。文件无效时拒绝启动。
- **脱敏**：只替换已知的秘密（Gateway Key 的签发格式、本进程解析过的凭据与订阅令牌、管理令牌、用户规则），不做通用的密钥识别；占位符是本进程密钥下的 HMAC，同值同占位符。还原只发生在答复中工具调用参数里，在面向客户端的写出层按入站协议进行，因而直通与翻译共用一条路径。缺省开启。
- **网关自己的调用**：视觉描述（以及之后需要模型的内部调用）走网关的完整路径：一个只监听 127.0.0.1、只接受本进程随机令牌的内部监听器；每次调用是独立的账本条目（`agent` 为 `harnesshub-<用途>`）。内部调用不再触发视觉兜底。原先使用一个可用任何模型、没有配额的内部 Key，账本条目没有 `keyId`；2026-10-05 起改为以触发请求的 Key 发出，受它的白名单、预算、每分钟请求数与局域网规则约束，并限制每个请求的描述与搜索次数，见 [ADR 0032 补充二](0032-group-rules-and-classifier.md#补充二网关自己的调用记在触发它的-key-名下)。
- **视觉兜底**：翻译的请求在元数据未声明图片输入时、直通的请求在元数据明确不含图片输入时，由设置的视觉模型描述图片（缓存、并发 4）；直通请求因此改为翻译。本轮图片描述失败时该候选以 502 `vision_failed` 跳过。
- **搜索模拟**：在翻译的回合中由网关执行：函数工具 `web_search(query)`、注册的搜索 API、至多 6 轮；客户端看到其协议自己的搜索形式（Anthropic 的 server tool 块、Responses 的 `web_search_call`），带网关标记，回到历史中时转成文字。会自己搜索的上游（按主机）在直通时保留原工具。
- **图像端点**：`POST /v1/images/generations` 直通到声明了 `imageEndpoint` 的 provider，Credential 转移、脱敏与账本照常；新增 provider 字段而不是新的线协议，因为图像请求不参与协议翻译。

## 考虑过的替代方案

- **通用的密钥模式识别（Magpie 的 API key、JWT、私钥等规则）**：会替换用户有意交给模型的内容，并且在不知道值的情况下无法保证工具参数中的还原正确；所有者要求的范围是已知秘密。
- **在所有文本中还原占位符（Magpie 的做法）**：会把秘密写回模型的文字答复与日志式的输出；只在工具参数中还原即可让工具工作。
- **视觉与搜索的内部调用直接调用上游**：需要第二套候选选择、熔断、凭据与账本逻辑；经内部监听器复用同一路径。
- **搜索由另一个“会搜索的模型”执行（Magpie 的首选）**：依赖订阅或特定厂商；所有者要求的后端是搜索 API。
- **`images` 作为新的 `WireProtocol`**：协议闭集在翻译、编码与解码中被穷尽处理，图像请求不参与其中。

## 后果

- 一些请求不再按字节直通：被脱敏的直通请求重新序列化，需要视觉兜底或搜索模拟的直通请求改为翻译。
- 内部监听器在第一次使用时启动，处理函数关闭时关闭；它只接受本进程的令牌。
- 新的设置文件与管理接口；`hh provider add --image-endpoint`。
- Chat 的 `web_search_options`、Gemini 的 `googleSearch`、`/v1/images/edits` 与自动选择画图模型不在本次范围内。

## 验证要求

- 网关单元测试：占位符经工具调用往返（流式片段中被切开的占位符）、三轮之内没有泄漏、关闭脱敏、Anthropic 直通的往返；视觉描述、缓存、描述失败与未设置时的行为；搜索的 Anthropic 与 Responses 呈现、历史中的标记、6 轮上限、各家搜索 API 的答复解析；图像的直通、费用、Credential 转移与拒绝。全部只用回环假服务，不调用真实的搜索或图像 API。
- 集成测试：经守护进程的设置接口与 `hh gateway` 命令，管理令牌与上游凭据不发往上游，图像调用经守护进程的网关。
- 未验证：真实的 Tavily、Brave、Exa、Firecrawl、SearXNG 与真实的图像 API；真实客户端（Claude Code、Codex）对网关搜索块的显示。

## 修订（2026-10-05，第二轮安全审查 G 组）

- **用户脱敏规则的回溯（M6）**：规则在守护进程的事件循环上对每个请求的每个字符串运行，一条会灾难性回溯的规则（`(\w+\s?)+$`，45 个字符超过 40 秒）可以来自备份、同步或接口，让守护进程停住。决定在所有入口用保守的静态检查拒绝这类规则（[regex-safety.ts](../../packages/core/src/regex-safety.ts)：反向引用；重复多于一次、里面还有重复、可选部分或分支的分组；两个无上限、字符可能重叠、之间只有可选部分的重复），另给一次脱敏一个时间预算（`gateway.limits.redactionBudgetMs`，默认 1 秒），超过时这个请求以 503 `redaction_timeout` 失败。考虑过线性时间的引擎：V8 的实验引擎要用进程级标志打开，RE2 一类要引入原生或 WebAssembly 依赖；也考虑过在 Worker 线程中运行规则以便超时终止，但脱敏是同步路径，改为异步牵动所有调用方，每个请求还要复制整个正文。静态检查偏保守（`(?:-[0-9]+)*` 这类其实无歧义的写法也被拒绝，可改用字符类），预算只在字符串与规则之间检查，单次匹配不能被打断，这一点靠静态检查兜住。更早写下的设置文件中不符合的规则在启动时不生效并记日志，而不是让守护进程无法启动。
- **搜索 Key 只接受存储值（M5）**：备份与同步中的搜索 Key 若是外部引用，守护进程会读取它指向的任意秘密并发往备份给出的搜索地址。由于 `hh gateway search add` 总是把 Key 写入密钥存储，外部引用只可能来自恢复，因此恢复与同步一律不带入这样的后端并写明引用指向什么（`search.refused`），而不是像 Library 那样逐项检查。
- **搜索地址不带凭据**：`baseUrl` 中的 `user:password@` 会出现在设置视图与备份中，现在被拒绝；Key 用后端自己的 Key。
