# ADR-037：复制一轮的诊断信息

状态：accepted，2026-10-12。依据用户授权的审批代理（Fable 5.1）对排序第 3 项 D 的条件。对应[第一链路调研](../research/first-chain-products-2026-10-11.md)的差距 10。

## 背景

- 一轮回复出了问题时，用户要说明发生了什么，只能截图或复制回复。版本、阶段耗时、结束原因、清理状态和原程序日志都在 Hub 里，但界面上拿不到。
- 原程序的 stderr 可能写出用户的路径、它自己的凭据或环境变量；Hub 注入的 Provider 密钥也可能出现在其中。这些内容不能进入浏览器。

## 决定

1. **收集。** 每轮开始时，驱动记下原程序 stderr 的位置；结束时，Runtime 取本轮写出的部分，只在当前服务的内存中保留最后 4 KiB，最多保留 64 轮。复用保留进程的回合从复用时起算。服务重启后，之前各轮的 stderr 不再有。
2. **接口。** `GET /api/v1/sessions/:id/runs/:runId/diagnostics?content=0|1` 在请求时拼装，服务端不保存拼好的文本。参数无效返回 400，回合不存在返回 404，未登录返回 401。
3. **内容。** HarnessHub 构建号、Node 版本、操作系统与架构；Harness 与控制入口；原程序在本轮报告的名称、版本和协议版本；当前安装的产品版本与控制入口版本；回合状态、原生模型与设置、是否复用或交出保留进程；各阶段耗时；后端结束原因、错误代码、停止与取消请求；清理状态（是否关闭、退出码、信号、协议故障代码）；本轮事件数（按类型）；工具、提示和产物的数量；本轮 stderr 的最后 4 KiB。全文不超过 64 KiB。
4. **对话内容。** 默认不含。用户勾选“包含这一轮的提示词与回复”后，只加入这一轮的提示词与回复文本，不含附件、工具内容和其他轮次；超出总量时先截短回复。首行写明“HarnessHub 诊断 · 不含对话内容”或“含对话内容”。
5. **清洗，在服务端完成。** 所有来自原程序的文字（stderr、原程序报告的名称和版本、结束原因）和勾选后加入的对话内容，依次：经过 Hub 既有的 Provider 脱敏器；隐去密钥样式的字符串（`sk-…`、GitHub 与 AWS 令牌、JWT、`Bearer`/`Basic` 后的值、`token`、`password` 等键后的值）；隐去环境变量写法 `NAME=value` 中的值；把绝对路径、`~/` 路径、`file://` 地址和 Windows 路径换成“[路径]”；把本机账户名换成“[用户]”。被隐去的部分有标记，不会悄悄删掉，行结构保持不变。
6. **界面。** 执行详情中有“复制诊断信息”按钮和“包含这一轮的提示词与回复”勾选项（默认不勾选），只对已结束的回合显示。文本直接写入剪贴板，页面不保留；复制后说明是否含对话内容。
7. **原程序日志里的对话内容。** 原程序可能把收到的提示词写进日志（真实验证中 Hermes 0.12 每次都记录“Prompt on session …: <提示词开头>”）。不含对话内容时，stderr 中出现本对话任一消息开头（前 32 个字符，短于 4 个字符的消息不查）的地方，从那里到行尾换成“[对话内容已隐去]”；第二行说明这一点。

## 影响

- `HarnessControl` 增加可选的 `diagnosticMark()` 和 `diagnosticsSince(mark)`。ACP、Codex、Pi 驱动由已有的 stderr 窗口提供；经 Provider 连接的回合，外层的脱敏包装会先替换密钥。
- 新增读取接口，不改变业务格式，也不新增持久数据。
- 清洗是按模式进行的，可能误伤普通文字（例如日志里的 `LEVEL=INFO` 会被隐去值），这是有意取舍：宁可多隐去，也不外泄。

## 不做

- 不收集原程序自己的日志文件（例如 `~/.hermes/logs`），也不读取它们的配置。
- 不把诊断信息上传到任何地方；只复制到剪贴板，由用户决定如何使用。
