# ADR-033：本机目录缓存、就绪状态与探测会话

状态：accepted，2026-10-12。依据用户授权的审批代理（Fable 5.1）对“读取模型目录的副作用”的决定（记录在 [ADR-031](0031-hermes-and-deepseek-harness.md)）和本阶段优先级 P4、P5，以及[第一链路调研](../research/first-chain-products-2026-10-11.md)的差距 1、2。

## 背景

- 选择 Harness 时要读取它的本机模型目录。Hub 为此启动原程序；ACP 只能从会话中取得目录，所以每次读取都会在原程序里建一个空会话（dsh 会把它列进自己的会话列表，Hermes 0.12 会写入 `state.db`）。原来的缓存只在内存里保留 60 秒：Hub 重启后，或隔一分钟再选同一个 Harness，又会启动一次、再建一个空会话。Hermes 每次读取约需 5 秒。
- 选择器只显示版本。能否连接、是否已登录、启动要等多久，都要发出第一条消息后才知道。
- Hermes 0.12 未配置提供方时，`initialize` 的响应不带 `authMethods`，Hub 把它当作协议错误，用户只看到“无法读取模型列表”。ACP 规范中这个字段可以省略，默认是空列表（官方 TypeScript SDK 1.8.0 也按空列表处理）。

## 决定

1. **目录缓存。** 按请求（入口、工作区配置、所选模型）、安装/配置指纹和读取它的 Hub 构建复用目录，最长 24 小时，最多 32 条；保存在数据根的 `native-catalogs.json`（权限 600），跨重启有效。“刷新本机模型”总是重新读取；读取失败或报告需要登录时删除该条。只保存契约中的字段，写入前按读回时的同一套校验检查，超出界限的目录照常返回，但不保存。指纹只看文件身份（设备、inode、大小、修改时间），不读文件内容，也不含凭据。Hub 构建标识是全部编译产物（按文件名和内容）的摘要：目录的内容由驱动决定，换了构建就重新读取（2026-10-12 补充：真实验证中，升级后的 Hub 仍复用了旧构建读出、缺少新选项的 Codex 目录）。
2. **派生数据的处理。** 这个文件只是缓存，不是证据来源：验收与能力判断以真实读取和回合为准，界面保留“刷新本机模型”。这个文件无法采用时（不是私有普通文件、内容损坏、版本未知），Hub 不改动它，启动时在 stderr 报告一次，本进程只在内存中保留观察。写入失败也报告一次，之后同样只在内存中保留，不影响目录读取。写入串行进行，并原子替换（临时文件、fsync、rename）；只有数据根的所有者写入，关闭时等待最后一次写入。启动时删除本文件中断写入时留下的临时文件。
3. **就绪状态。** 每次目录读取的结果记为该入口的就绪状态：已就绪（附原程序是否说明已登录）、需要登录或配置、读取失败（只记稳定的错误类别，不记原文）。Hub 自身的原因（取消、并发上限、关闭、存储）不改变就绪状态；20 秒内没有返回记为 `NATIVE_CATALOG_TIMEOUT`。不为显示状态而在后台启动任何 Harness，没有读取过的入口不显示状态。
4. **启动用时。** 取该入口最近 5 个带阶段计时的回合（在最近 100 个对话内），以中位数作为“通常启动用时”。选择器显示“启动约 N 秒”。新对话第一次使用某个 Harness 时，启动阶段显示“（通常约 N 秒）”；同一对话里已有它的回合时，仍显示“（上次约 N 秒）”。
5. **接口。** `GET /api/v1/harnesses/readiness` 只读返回就绪列表，`/api/v1/state` 也带上这份列表。界面在每次目录读取后、每个回合结束后刷新。
6. **探测会话。** 目录读取建出的原生会话（ACP `session/new` 成功返回的标识）按入口记录，最多 512 条，跨重启保留。“本机会话”默认不列出这些会话（已被对话持有的除外），并提示“已隐藏 N 个 HarnessHub 读取模型列表时建立的空会话”；点“显示”可查看全部（`probes=include`）。
7. **ACP `authMethods`。** 省略时按规范视为空列表；存在但不是列表仍是协议错误。没有 `type` 的认证方式属于 agent 类。
8. **Hermes 的提供方。** Hermes 只在解析到提供方凭据时才声明 agent 类认证方式（0.12 源码 `acp_adapter/auth.py`；上游另有一个只用于设置的 terminal 方法）。没有 agent 类方法时，Hub 不建会话，直接报 `NATIVE_AUTH_REQUIRED`，界面提示在终端运行 `hermes model`（Hermes 官方 ACP 文档给出的配置命令）；有 agent 类方法时，目录报告“已登录”。其他 ACP 代理声明的认证方式只说明它提供哪些登录方式，不改变就绪判断。模型目录接口把 `NATIVE_AUTH_REQUIRED` 与已有的两个认证代码一样，返回 `authentication: "missing"`。

## 影响

- 数据根新增 `native-catalogs.json`。删除它只会让下一次选择重新读取目录；回退到旧版本时，旧程序不读取它。
- 文件格式 v2 记录构建标识。读到 v1 文件时保留其中的就绪记录与探测会话，丢弃目录，下一次写入改为 v2；更旧的 Hub 读到 v2 文件时会报告并保持原样。
- 本版本之前建出的探测会话，以及建出会话后才失败的读取（例如所选模型不在目录中）建出的会话，都没有记录，仍会列出。
- 大多数 ACP 代理不说明登录状态，对它们来说，“已就绪”表示原程序接受了会话并给出了目录；登录与额度仍由原程序在发送时核实，悬停提示会写明这一点。
- 需要登录时，只对官方文档写明命令的产品给出具体命令（目前只有 Hermes 的 `hermes model`），其余给出通用说明。

## 不做

- 不在后台预热或定期探测各 Harness：这会启动用户的程序及其 MCP 服务器。冷启动本身留给 ADR-030。
- 不调用原生 `authenticate`，也不代为运行原程序的登录流程。
