## 2026-11-11

- **上下文桌的挂载做在 Claude Code 与 Codex 上：Hub 起的每个原生进程带 Hub 的地址和自己的令牌，工具经管家装进用户级配置。** 一个原生进程只服务一个 Hub 会话（还没有进程池），所以环境变量 `HARNESSHUB_URL`、`HARNESSHUB_SESSION` 就是会话标识：令牌在启动进程时现铸、进程结束即撤、不进宿主类标识（否则每回合换一份 TMPDIR），Hub 重启后旧令牌不认。工具条目（名字 `harnesshub`，Hub 所用的 Node 加 `cli/hub-tools.js mcp`）走管家现有的 MCP 清单、备份与回读，只写变量名：Codex 用 `env_vars` 转发（官方文档与源码确认，没有真机跑过）；Claude Code 的 MCP 进程默认继承环境（文档确认，没有真机跑过），条目里仍写 `${变量}`，在 Hub 之外用它时会在 `/mcp` 里报一条变量未设置的警告、工具读到的是变量名原文，所以工具只认 `readTableEnv`。Hermes（会话在用户的网关里）与 OpenClaw（桥拒绝按会话传入）带不过去；OpenCode、DeepSeek Harness 按文档应可用，没接。进程池落地后一个进程会有多个会话，要改走 ACP 的 `mcpServers` 或 Codex 的 `thread/start` 按会话传入。合成测试通过，未真机验证。
- **普通会话的方向：Hub 统一管理任务的全部上下文，Harness 是执行者，它的原生会话只算工作记忆。**（用户决定）架构向 T3 Code 看齐；主线是“对话里换一家接着做”并设法补上损失，同时做委派（先只由用户发起）。上下文“既发菜也能自己夹菜”：Hub 推少量关键内容（进展卡、最近几轮、原话），其余由 Harness 经 Hub 的工具服务按需读回；用户接受因此给每个会话多挂几个工具。工具服务以 MCP 为首选、命令行兜底，逐家真机验证后定；工具由管家直接装进各家 Harness 的用户级配置（用户决定），在管家里可见可卸，不在 Hub 会话里时不做事。群组协同以后再议。设计只在讨论稿，未实现；调研见 research/。
- **减法之后的一轮独立审查：状态机不丢内容、不谎报、补发有界**（探索器约 6,000 万次转换零丢失，14 处变异全被测试抓到）。它找到并已修的四处：OpenClaw 上带内容或附件的清空词不再被当成清空（只认单独一个词，与 Codex、OpenCode、DeepSeek Harness 一致；Hermes 带文件或音频时也不接管）；像消息一样进入上下文的命令回合（效果为 keep，如技能命令）算事实、会进交接单；从 v12 迁移时只要可能回退过就整份重发一次；Driver 报了清空就记清空边界，不管那次关闭是否干净。已知不改：OpenClaw 没法确认送达，对它做不到只补增量。

- **减法做完了，真机两个方向都走通。** 相对减法之前删 2.1 万行；接力相关源码从 8,040 行到 4,349 行。每个绑定只记：第几个原生会话、看到哪里、清空边界、未确认的包、下次是否整份重发。设置只剩一项（换 Harness 时附上之前的对话）。目标与现状见 [slim.md](../proposals/relay/slim.md)，真机见[走查记录](../verification/relay-real-walk-2026-11-11.md)。
- **Codex、OpenCode、DeepSeek Harness 也有清空了。** 单独输入 `/clear`、`/new`、`/reset`（不带别的字与附件）由 Hub 接管，开新的原生会话；带了内容的仍是普通消息。
- **明确要求附上而附不了时，这一条失败、草稿保留**；没有明确要求时自动只发原话并说明。不悄悄改写用户的明确要求。
- **交接单的说明加回一句**：记录里用户提过的要求和约束仍然有效，除非用户后来改了口。（用户同意。）

- **真机走通了一次。** Claude Code（haiku）与 Codex 经 Hub 走 9 个回合：换过去、换回来、原地继续、刚发出就停止、清空，全部完成；事后核对一次没跑，“送达不明”没有出现。见[走查记录](../verification/relay-real-walk-2026-11-11.md)。只有这一对、各一趟。

- **Hub 起的原生会话归 Hub 管。** 不支持用户同时在原生界面里续写同一个会话。据此，“事后读对方历史核对送达”“探测原生清空与回退”可以退出主路径。（用户决定；依据见[同类产品调研](../research/similar-products-2026-11-11.md)。）
- **清空由 Hub 接管。** 所有 Harness 的清空都是“开一个新的原生会话”，不再有“清空待确认”。原生的清空命令从菜单里藏起，或被 Hub 接住。（用户决定。）
- **改为快速迭代。** 取消文件归属登记与它的检查关卡、先冻结契约再实现、每个决定一份 ADR、审批代理、多轮独立审查、不变量表与测试用例登记。保留：提交前检查与全量测试通过、测试用真实存储与进程通信、不碰真实配置与凭据、推送先问、证据等级分开说。约定见 [AGENTS.md](../../AGENTS.md)。（用户决定：“规则限制比较多，不适合快速迭代开发了”。）
- **接力要做减法，按真机结果来。** 候选：事后核对退出主路径；厂商按 Harness 名字算，同意只留首次一行提示和日志；严格模式整个去掉，设置项收到 2 个以内；探针门控改成静态声明加升级时的契约检查；交接单只放事实、收成两档。不砍：永不因历史太长卡死、省略有账、送达不明不丢原生会话、对用户可见、取消与失败回合的处理、命令回合不带交接单、水位按追加序号。先在真实的 Claude Code 与 Codex 上把现有功能走一遍，再动手。
